# 产品线统一管理

产品中心按「产品线 → 产品」组织目录。独立管理产品仍保留原空间；只要产品线中还有尚未启用管理的产品，就可以把产品线作为一个 AIMS 管理主体，并将所选产品创建为该空间的功能模块。

## 数据与行为

- Assets 是产品与产品线目录的事实源。AIMS 不创建或改写 Assets 产品主档。
- `product_line_workspaces` 绑定产品线编码与 AIMS 空间，保存启用时的产品线名称及来源水位。空间使用保留命名空间 `~line-` 加产品线编码 SHA256 的前 56 个十六进制字符；普通产品启用不得使用这个命名空间。工作台对用户显示产品线名称与编码。
- `product_component_sources` 保存每个来源产品到统一空间、功能模块的唯一关系。同一来源产品不能同时属于多个统一空间；带来源的模块不能直接删除。模块名称与描述可以按正常模块管理维护，来源关系不随编辑、移动或目录刷新漂移。
- 统一启用必须指定有效目录用户作为初始经理，并从当前目录证据中选择要纳入的来源产品（至少一个）。经理关系只授予对象范围，不增加角色动作权限。启用原因不再采集。
- 已存在独立空间（包括归档空间）或已有来源模块关系的产品保持独立，不会被合并：选中这类产品会被拒绝，未选中则不影响其余产品统一管理。当前生命周期不允许接入的产品同样只约束自己。整条产品线的产品全部已被管理时不再可统一。独立启用和统一启用共用目录控制锁串行化；目录激活也使用同一锁。不会仅根据前端当前页、搜索结果或状态筛选判断资格。
- 空间、经理、所选模块、来源关系、审计和幂等回执同一事务提交。相同用户/键/请求重放原结果，异内容返回 409；重放仍校验新授权、当前来源水位和目录用户证据。
- 目录刷新不会自动变更已启用的模块集合。源产品移线或从目录消失时，保留原来源绑定；新增产品不会被静默独立启用或自动分配权限。后续纳入新来源产品的专用同步操作不在本次范围。

## API

`GET /api/v1/products?tree=true`：按产品线分页，沿用 keyword/productLine/status 筛选，返回 `groups`（line_code/label/total/management_product_code/status/can_unify）和目录代次。total 为筛选且授权后的产品线数，组内 total 为筛选且授权后的来源产品数，不把统一空间自身计作一个下属产品。

`GET /api/v1/products?tree=true&childLine=TY&page=1&pageSize=20`：展开指定产品线，独立分页返回 items；空 childLine 表示未分类。来源模块返回 management_product_code/component_id，权限以实际统一空间为准。普通平铺列表保持兼容，统一空间替代已映射来源产品，避免产品切换器将模块当成独立空间。

列表的 `can_unify` 仅在 BFF 确认全租户 onboard 权限后计算，检查生效代次中整条产品线：尚无产品线空间，且至少有一个产品未被独立管理。它只是操作提示；保存重新验证 Assets 事实和数据库冲突。

`GET /api/v1/product-candidates?mode=line&productLine=TY`：要求全租户 products:onboard，按固定目录水位完整读取整条线（每页 100、最多 1000 个产品），返回统一启用预览；不接受浏览器提供源产品列表。

`POST /api/v1/products` 新增互斥输入形态 `{ productLine, managerUid, productCodes, expectedWatermark }`，仍要求 Idempotency-Key 与全租户 products:onboard。单产品形态继续使用 productCode。`productCodes` 是本次纳入的来源产品编码，非空且不重复，最多 1000 个；浏览器只能选择产品，是否属于该产品线、是否可接入由目录证据判定。BFF 重读整条产品线，必须与预览水位一致、所选产品均在目录中且 onboardable，再核对负责人 active 状态并重新获取短时授权；Runtime 另行拒绝所选产品中已被管理的项。

内部 `POST /v1/aims/internal/product-line-onboard` 复用 `aims.write aims:products:onboard`，要求可信 Aims 身份、签名用户 actor、租户及部署绑定。读取继续使用 `aims.read aims:products:view`。跨应用读取继续使用既有 Assets `assets:product:read` 与 Foundation Directory helper；没有新增 service capability、grant 或后台任务。

## 安装与验证

先在目标 AIMS 数据库执行幂等迁移 `migration_v5.37_product_line_management.sql`，再更新 Runtime 和 AIMS。不得先上线新页面却只部署前端。迁移只增加两张表，无存量产品合并或数据搬迁。

MySQL 回归使用全新 `/tmp/hzy-product-center.*` 私有 socket 与随机测试库，覆盖 105 产品分页、经理/无权限范围、完整资格判定、归档冲突、绕开已管理产品与不可接入产品的部分统一、并发独立与统一启用、回执重放、异载荷、过期授权/来源、来源截断和审计失败回滚。浏览器以真实页面和模拟 API 检查桌面 1440px、手机 390px 的树形展开、确认表单与成功后的模块展示；不替代目标租户的 API/授权验收。


## 产品线名称与首页筛选（2026-09-13）

产品中心的名称来自 Assets 产品目录的当前已激活同步代次。统一空间接入时的 `line_label` 只作目录缺失时的回退；首页分组、产品切换列表、按产品线名称搜索及统一工作区标题优先使用最新同步名称，读取不改写原接入身份或水位。Assets 产品线名称修改后，具备接入权限的用户须在产品中心「同步产品目录」，完成后名称生效。

首页产品线筛选改为可搜索下拉框，显示「名称（编码）」并按编码精确查询，提供「全部产品线」及重置。选项通过既有带用户范围的产品树接口独立加载，不随关键词或管理状态缩减；URL 筛选可恢复。沿用有界逐页读取，加载失败或截断明确提示，不增加 Assets 目录授权旁路。

验证：真实隔离 MySQL 回归覆盖名称首次补齐、再次改名、空名称回退、仅统一空间范围的读取与中文搜索、无权限查询，以及接入快照保持不变。浏览器和测试环境结果见测试部署记录。
