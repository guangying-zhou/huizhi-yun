## 目标与边界

研发视角主入口固定为「需求池 / 版本计划 / 产品结构」，默认进入需求池。保留概览、销售与交付、经营与管理、设置等一级视角；保留既有授权和领域事实，导航简化不改变对象权限，不删除历史候选功能、周期或评分数据。

- 需求池：统一收集新想法、评审和排入版本，模块作为分类上下文。
- 版本计划：目标与投入、需求范围、计划确认、项目承接及验收发布连续可达；版本矩阵、发布比较、路线视图和跨版本项目汇总放在局部工具中。旧周期规划明确为高级入口。
- 产品结构：模块树和模块功能在同一工作区，按需展开并分页；保留模块维护和历史功能管理，新想法引导新增需求。
- 设置：评分模型归入高级规划配置。

## 验收条件

1. 研发默认进入需求池，二级仅三个主入口；旧 features/components 链接到结构，planning/cycles 等归入版本，models 归设置。
2. 选择模块时，当前页面直接显示对应功能；模块树、功能列表仍用真实分页，已有候选功能可查。
3. 新需求带入当前模块；功能详情和旧深链可返回正确结构上下文。
4. 版本页面可定位计划、范围、确认、项目承接与验收发布；旧 cycle 版本可继续访问原流程。
5. 高级工具从明确的业务入口进入；GTM 复用版本、矩阵及对比页保留视角。
6. 空、加载、失败、只读状态可理解，刷新重试可用；不将导航可见性当作服务端权限。
7. 类型检查与相关测试通过，1440 / 390 浏览器检查无新增重叠、页面横向溢出或运行错误；真实测试环境验证与 mock API 证据分开记录。
