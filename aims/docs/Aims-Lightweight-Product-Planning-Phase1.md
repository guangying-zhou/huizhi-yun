# 产品轻量规划第一阶段：实施方案与计划

日期：2026-09-12。状态：第一阶段代码已完成，领域／接口及隔离浏览器验收通过；续修 Nitro 请求类型后，Aims 全量类型检查也已通过。已部署到 CF 测试环境（Aims Worker、本机测试 Runtime 及 v5.38 迁移），生产环境未部署；详见 §9.3。

## 1. 交付目标

产品负责人无需创建独立规划周期、填写评分或分类投资预算，即可完成：

1. 在产品或模块下登记需求，产品层汇总且不重复计数。
2. 创建版本草案，填写版本目标、计划期间、负责人和可用人日／预留。
3. 在版本内选择需求，确认本次范围、粗估投入、顺序和验收标准。
4. 查看已选范围总投入、未估算项、余额和阻塞原因，调整后确认计划。
5. 从已确认范围单条转交／关联项目需求，沿用项目评审、基线与执行流程。

本阶段包含上述完整纵向链路、存量兼容、权限、并发、幂等、迁移和桌面／移动端验收。后续阶段承担批量项目转交、完整顺延编排、产品线跨产品需求拆分、共享团队容量统筹及季度预算。现有发布和客户采用链路保留。

## 2. 现状与决定

- `product_requests` 目前只有产品归属；模块直接关联长期功能。新增可空模块归属及父模块汇总筛选。
- 现有版本内容以 `product_version_features` 保存，并可关联 `product_planning_items`。复用这些身份，不另建一套“轻量需求／版本范围”。
- `ValidatePlanningDeliveryTx` 当前强制开放周期、有效评分和正式选入。增加由服务端持久化的版本计划决定路径；不得假造周期、评分、预算，也不得仅隐藏前端或删除旧门禁。
- 原周期评分路径保留为高级规划。存量版本保持原路径；新 UI 创建版本默认轻量规划。规划方式必须持久化，不能由每次命令临时选择以绕过已有约束。
- 需求的采纳决定与交付安排分开保存／展示；排入草案不代表已承诺或已交付。
- Assets 产品／产品线主档、Console 目录与权限、Aims 项目及发布事实边界保持不变。

## 3. 产品行为

### 3.1 模块与需求

- 创建／编辑需求可选择同产品模块，也可不分类。旧调用省略模块字段时保留原归属；显式 null 清空。
- 需求列表提供全部／未分类／指定模块（含后代）筛选，分页与总数均在服务端执行；筛选变化回第一页。
- 模块页面提供“查看需求”“新增需求”，传递模块上下文。模块删除需检查需求引用。
- 产品结构入口将模块和功能目录关联展示，保留旧链接；不要求用户先建长期功能才能提交或排期需求。

### 3.2 版本工作区

- 新建版本保持轻量；创建后进入计划工作区。
- 工作区包含计划概览、需求范围、研发交付、验收发布四个连续入口；现有版本详情和发布记录可复用。
- 计划字段：目标、计划开始／结束日期（结束与现有计划发布日期采用同一事实源）、可用人日、预留人日。负责人沿用版本业务负责人。
- 已选范围显示来源需求、模块、范围说明、粗估人日、验收标准、顺序、交付／转交状态。候选需求支持搜索、分页和模块筛选。
- 产品需求列表和详情提供“排入版本”，选择版本并使用同一表单；成功返回对应版本，展示已安排版本与草案／确认状态。
- 创建范围由服务端在一个事务中保存来源关系、规划事项、版本范围、计划变更与审计。默认复用来源标题和说明，不重复录入。重复提交幂等；已存在相同来源的范围提示查看／编辑，不静默复制。复杂拆分保留后续扩展点。

### 3.3 草案、确认及变更

- 草案允许未知投入、未填预算、缺验收标准和日期，明确展示待补齐；未知不是 0。
- 确认要求：有效目标与计划日期、当前有效负责人、明确且非负的预算／预留、至少一个有效范围、每项大于 0 的人日估算和验收标准、已知前置依赖可行、总投入不超可安排容量。预留不能大于可用人日。
- 可安排容量 = 可用人日 - 预留；不再减一次已在“可用”中扣除的其他项目投入。界面说明可用人日由负责人扣除其他承诺后填写。
- 所有汇总覆盖完整版本范围，不受分页、搜索影响。一个范围计一次；不按来源需求、项目关联数倍增。
- 确认保存计划／范围修订和估算快照，保留确认人、时间。范围、估算、日期、预算变化使确认失效，展示“需重新确认”；已经转交的范围显示影响，不能覆盖项目基线。
- 已确认计划的范围、预算、日期变更要求原因；草案普通编辑自动审计，不强制填写冗余原因。
- 已发布／归档版本不可通过轻量接口改写。轻量版本进入开发须有当前有效确认。旧高级规划不得用新接口绕过评分决定。
- 既有规划事项若有依赖，确认和项目转交都重验；不能把同版本但顺序在后的前置显示为已解决。未提供依赖录入 UI 不等于可以忽略既有依赖。
- 简单来源需求首次排入不要求独立评审页面：具备需求决定权限时可在排入动作中明确确认采纳；否则只允许安排已采纳需求。拒绝、合并、暂缓需求不得静默变为正式交付。

### 3.4 单条研发衔接

- 从轻量版本已确认范围转交项目，复用已有幂等项目需求创建／关联及权限检查；新决定依据必须绑定实际版本／范围／确认修订。
- 草案、失效确认或已移出范围不能新转交。不得以浏览器提交 `mode=simple` 绕过授权和决定校验。
- 保留来源需求、规划事项、版本范围和项目需求关联，不把项目草稿直接标为基线。
- 用户可查看承接项目／需求；批量转交不在第一阶段。

## 4. 接口工作契约

浏览器提交 camelCase，Runtime snake_case，标准 `{code,data}` 和命令 `{value,...}` 回执。新计划响应采用 camelCase，存量接口响应保持原格式。三方详细 wire contract 维护在 [API 契约](Aims-Lightweight-Product-Planning-API.md)。所有命令要求 Idempotency-Key、当前用户委托、对象范围授权和预期修订。

| 浏览器接口 | 用途 |
| --- | --- |
| 现有 requests GET/POST/PATCH | 增加 componentId（可空）；列表 componentId / unassigned / includeDescendants，增加模块信息与安排摘要 |
| 现有 versions POST | 增加 planningMode=`simple`（新 UI 默认）／`cycle`；兼容旧调用和存量版本 |
| GET versions/:versionId/plan | 返回计划、全量汇总、当前修订与确认状态；不产生写入 |
| PATCH versions/:versionId/plan | 保存目标、开始日期、计划发布日期、可用／预留人日；使旧确认失效 |
| GET versions/:versionId/plan/items | 分页读取已选范围及来源、估算、模块、安排状态 |
| POST versions/:versionId/plan/items | 以 requestBizId、expectedRequestRevision、本次范围、estimatePersonDays（可空）、acceptanceCriteria、sortOrder 创建范围 |
| PATCH versions/:versionId/plan/items/:scopeId | 修改本次范围、估算、标准及顺序，保持来源身份 |
| DELETE versions/:versionId/plan/items/:scopeId | 从草案／计划移出尚未执行范围，留审计；已有执行／发布引用时拒绝并提示后续顺延流程 |
| POST versions/:versionId/plan/confirm | 原子校验预算、全量范围、依赖、修订并冻结确认快照 |
| 现有 planning-items/:itemId/handoffs | 增加持久化轻量版本决定依据，保留高级周期原路径 |

GET plan 的浏览器响应含 `planningMode`、`planStatus`（draft/confirmed/stale）、`goal`、`startsOn`、`plannedReleaseDate`、`availablePersonDays`、`reservePersonDays`、`workspaceRevision`、`versionRevision`、`planRevision`、`scopeRevision`、`confirmation`、`summary`（完整版本的 selectedCount、estimatedPersonDays、unknownEstimateCount、remainingPersonDays、issues）。Runtime 保持 snake_case；稳定 issue code 在界面映射为中文说明。投入统一沿用定点百份数／十进制字符串规则。缺值为 null。

权限复用现有 product_requests create/edit/decide/view/handoff、product_priorities edit/handoff/prioritize、product_versions edit/view/accept/publish 的职责；不能新建宽权限绕过。BFF 和 Runtime 均校验实际需要的各项权限。新增内部路由尽量复用已有精确能力的相同业务语义；确需新增 capability 时补 manifest、grant 初始化／核验及契约，不新增未授权服务客户端。

## 5. 数据与兼容

- 增量迁移预留 `v5.38`，更新规范 schema。旧请求模块为空，不按功能或名称猜测。
- 版本持久化 planning_mode，旧版本为 cycle；新增计划元数据、范围估算和不可变确认记录。可采用一对一扩展表隔离旧 SQL，但不能平行维护版本日期／范围事实。
- 范围继续复用 product_version_features、product_planning_items、product_planning_item_requests；确认记录引用真实修订，不伪造 priority_assessments。
- 老发布快照不重写；老高级规划和旧 API 回归继续通过。增量迁移可重复执行，范围／权限外键和删除约束必须覆盖模块引用。
- 不自动迁移已有统一产品线空间，不改变 Assets 业务键。
