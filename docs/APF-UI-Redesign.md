# APF 前端专业化设计与实施计划

日期：2026-10-05。设计基线：`caad2c3580de96145da4ad85ed91af8b5a77fb7f`（Enterprise 集成分支）。本次只交付设计；不包含页面实现、数据库变更或部署。

2026-10-06 更新：B1–B4 已有后续合入实现，本文件保留最初设计要求，不再把其中全部 R 项视为待实现。当前交付与剩余差距以 [APF 功能差距及 B5 计划](APF-Feature-Gap-Plan.md) §2 为准；B5 扩展为销售/财务业务闭环，原共享视图、批量及附件协作保留为后置子批次。

## 1. 目标、范围与证据

把已迁入 Enterprise 的客户、合同与财务数据组织成可日常使用的业务工作台。优先解决合同列表信息不足、排序不符合业务习惯、历史金额难以解释、账户与余额混排、迁移事项缺少明确下一步的问题。老 OA 是数据底线，不是设计上限；首屏服务于中小企业人员的判断与办理，不以仪表盘数量体现专业程度。

覆盖八个页面/工作区：客户、客户内联系人、合同（含历史详情）、法人主体、银行账户、余额、Altoc 迁移事项、Finance 迁移事项。联系人沿用客户详情中的工作区，本期不新建全局联系人路由。People 仅涉及负责人选择与身份匹配，不扩大为 People 全站重设计。

证据边界：

- 已核对现有页面、Host 组件、BFF 白名单、Runtime 查询及 W0/W1/W3 文档。字段存在于数据库或白名单，不等于当前列表已返回该字段。
- 本会话 Computer Use 原生通道启动失败，且 `iab` 不可用，未取得 hzy0 截图。以下为基于源码的数据与交互设计，不宣称已完成实页视觉评审。1440/390 的真实浏览器验收是各实施批次的完成条件。
- 未连接 hzy0 数据库，未修改其数据、配置或进程；未读取老 OA 目录的密钥、凭据或配置。线框均为结构示意，不包含生产客户名、个人信息或完整账号。
- W0 的 757 个客户、1,595 份合同、22 个银行账户是封存快照基线，不代表当前页面总数，也不作为前端硬编码或测试数据。

项目依据：[W0 基线](WizBiz-Migration-W0-Baseline.md)、[W1 模型](WizBiz-Migration-W1-Model-Design.md)、[W3 页面与权限](WizBiz-Migration-W3-Page-Design.md)、[UI/UX 规范](UI_UX_SPEC.md)、[标准列表页](STANDARD_LIST_PAGE.md)、[根执行约定](../CLAUDE.md)。Enterprise 使用原生 Host 页面，遵循当前根约定，不因旧规范中的通用 Console Shell 描述再套一层应用壳。

能力标记贯穿本方案：**E**＝复用现有接口/命令，仅改前端；**R**＝需要新增或扩充只读合同；**W**＝需要新写合同及显式权限设计。E 仍须验证对应字段实际返回及权限裁剪。R/W 未交付时不展示假指标、无效筛选或可点击的占位动作。

## 3. 共用页面与交互规范

### 3.1 布局和组件

列表固定为四层：页面标题与主动作 → 2–4 个有口径的汇总项 → 视图/搜索/筛选/列设置 → 表格与分页。标题接入 `usePageTitle`/现有 Host 标题机制，同屏不再重复 H1 或放第二个刷新按钮。无可用汇总接口时整层省略，不用当前页行数伪装全量指标。

1440 桌面：沿用 Enterprise 导航与内容间距，筛选主行保留搜索及最多三个常用条件，其余放筛选面板。表格默认约 7–9 个业务列，主名称可两行，其他长文本截断并可查看；行操作使用“查看/办理＋更多”，避免满行按钮。需要横向滚动时限制在表格容器，名称列固定，尾部操作可达。

390 手机：内容单列、两列汇总卡；主动作不挤占标题，筛选转全宽抽屉并显示已选数量；默认只露出名称、关键状态/金额与操作入口，其余列在同一表格内横向滚动，保留列设置。不把页面宽度撑至屏外。详情抽屉全屏，页签横向滚动且当前项可见，底部办理动作避开安全区。触控目标至少 44px。

优先复用 Foundation 的 `UTable`、分页、筛选、`CommonEmptyState`、`useListPage`、`useDebouncedSearch`、`useConfirm` 及现有 APF 选择器。按 Nuxt UI v4 的现有项目封装用法实施；颜色仅用语义 token，背景用 `bg-default/muted/elevated`。金额右对齐、使用等宽数字；正文默认 `text-sm`。不新增一套表格、弹窗或全站主题。

### 3.2 列表、视图和选中范围

- 所有对象列表按服务端 `page/pageSize/total` 分页，默认 20；仅在接口支持时提供 50/100。搜索防抖，筛选变化回第一页，旧响应不得覆盖新查询。返回列表恢复 URL 中的合法查询、页码、排序和滚动位置。
- 排序由服务端完成并带稳定第二排序键；不取全量、不循环取完分页、不在当前页上排序后声称全局有序。每页下文分别注明现状与目标。
- E 级个人视图仅保存本机偏好：列、已有筛选及已有排序。按租户、用户、模块、版本隔离；切换身份或权限收缩后清理不再允许的偏好。不保存对象内容、完整账号、临时解密结果；自由输入的个人信息不默认保存。跨设备、团队共享属于 W1。
- 系统视图只是现有筛选的组合，不另造权限。“我的负责”只有接口能按当前 UID 严格过滤后才启用，不能以显示名称或客户端筛页模拟。
- 首期仅允许勾选当前页明确行，切换筛选清空选择；未提供批量业务命令时不显示选择列。不能用“全选查询结果”暗含越过当前页。复制编码等本地动作不代表批量编辑能力。
- 新增批量写、导出、共享视图均走 §9 的 W 合同，逐条显示成功/失败与未执行；不把多次单条调用包装成原子事务。银行账号解密不提供批量入口。

### 3.3 全部八页共用的状态合同

| 状态 | 展示与恢复 |
| --- | --- |
| 初次加载 | 标题/筛选骨架及表格骨架，分页禁用；不闪现“暂无数据” |
| 刷新/筛选中 | 保留已显示行并标记更新中，禁止对过期选择提交；请求结束才更新总数和卡片 |
| 真空数据 | 说明对象用途；有创建权限才显示创建按钮；迁移空队列显示“当前没有待处理事项” |
| 筛选无结果 | 展示当前条件，提供清除筛选；不引导重复创建对象 |
| 403 / 无模块权限 | 清空此前缓存与选中，明确无访问权限；不把无权限作为零记录或零余额 |
| 局部关联无权限 | 隐去关联数量/金额及链接，显示受限说明；主对象可继续看；不泄漏隐藏子客户数 |
| 503 / 未安装 / 暂不可用 | 区分可识别错误码，保留筛选并重试；不显示“请申请权限”误导用户 |
| 网络错误 | 行内错误条＋重试，保留查询/表单；写入结果未知时沿用同一意图重试，不自动生成新请求 |
| 409 / 版本变化 | 保留草稿，对比服务端当前版本，明确刷新后重新确认；禁止静默覆盖 |

详情子页签独立加载、独立重试；某个财务服务失败不清空客户/合同基本信息。破坏性或停用动作经 `useConfirm`，展示对象、影响范围、历史保留说明。权限加载失败时不短暂露出办理按钮。

### 3.4 金额、日期、来源与时间线

1. 原签约额、当前合同额、有效合同额、回款额、未结算余额是不同事实。有效额按 W1 用户定义为扣除第三方等非本公司收入部分后的金额；历史 `prime_amount` 是原人工录入值，保留原值和来源，不按总额重新推导。NULL 显示“未记录”，不是 0。父子合同不得重复累加。
2. 金额使用服务端十进制字符串和项目格式化工具，不用 JS 浮点计算财务汇总；分币种显示。历史快照、重新核对结果、当前经营事实分组，不混成“累计收入”。
3. DATE 保留日历日期；W1 已定历史 `signed_at`、余额 `recorded_at` 从 Asia/Shanghai 源时刻转为 UTC 存储，展示与排序口径应转回业务时区。不能直接对 UTC `signed_at` 截日期。
4. 余额写明“最新已登记余额”和对应日期；多账户最新值的合计可能来自不同日期，必须说明“不同时点快照合计”。要回答同一日资金余额，需 R4 的截至日期口径，不能换个标题代替。
5. 时间线只展示有证据的事件：当前系统创建/修改、确认匹配、登记余额、显式业务动作、迁入记录。迁入时间与源签约/登记时间分开。没有源证据的审批、签章、收款事件不能补造。
6. 负责人：已确认但不能登录的历史人员仍可按已有受控读合同显示；`system:unassigned` 显示“待匹配”，新指派选择器排除保留主体、无效和不可登录 UID，服务端 owner guard 为最终裁决。原始人员信息仅在有权来源详情中展示，列表不复制迁移台账。

| 特殊状态 | 无客户可新建；层级不可见显示“上级受限”；有隐藏子项不显示其数量；无搜索结果可回到全部。其他状态执行 §3.3 |

客户详情采用概览头（名称、编码、状态、负责人、上级、行业/地区，最多八个重点字段）；编辑与负责人调整分成不同动作。页签为“概览 / 联系人 / 合同 / 开票资料 / 附件 / 来源与审计”。

- 概览：基本资料、组织层级、备注。W3CustomerOverview 的历史经营快照独立卡片，写明快照时点、包含子级与否及金额口径；与当前合同统计不得并排无标签比较。
- 联系人：§4.2；合同：R2 服务端按客户过滤并分页，不能取全部合同再过滤。返回客户保持页签和列表条件。
- 开票资料：复用现有详情资料，敏感字段依权限；只读展示不自动获得修改权。
- 附件：只有已存在且授权的附件/知识引用才展示；未接入统一附件读合同前省略页签，不放假的上传入口（R5/W3）。
- 来源与审计：复用 `W3SourceInfo`/迁移快照，历史来源默认折叠；完整审计时间线补 R5。没有审计接口时仅列确知的创建、更新和迁入信息，不伪造操作人。

| 状态 | 零待办显示已清理当前范围；候选不等于确认；无对应人员/源缺失保留证据；409 保留草稿并比较；请求未知沿用原意图，其他按 §3.3 |

事项详情以“问题 → 原值/候选 → 可用处理方式 → 结果”排序。联系人归属支持现有归属客户/关联已有联系人/接受现状；其他关联异常只开放合同中允许的方法。有效额超总额保留两个金额，接受现状必须填写原因，不直接改合同金额。详情审计事件未有读合同部分归 R5。

### 7.2 Finance 迁移事项

```text
1440｜Finance 迁移事项
     [合同余额差异·只读 N] [余额待认领 N] [同日余额冲突 N]
     [类型 ▾] [状态 ▾] [列]
     对象 | 问题摘要/日期 | 原值与核对值 | 状态 | 下一步 | 操作
     合同差异 → [查看证据]；待认领/冲突 → [办理]
390 ｜Finance 迁移事项
     [差异·只读 N] [待认领 N] [冲突 N]
     [类型 ▾] [状态 ▾]
     对象/问题        | 状态 | … →
     全屏详情：金额比较 → 证据 → 有权限且适用的办理区
```

| 项目 | 设计 |
| --- | --- |
| 默认/可选列 | 默认对象、事项类型、余额日期（适用时）、原值/核对值/差额、状态、下一步、操作；可选事项 ID、版本、来源批次/时间（R5）；不用统一“金额”混淆不同异常 |
| 默认排序 | E 同类型 ID ASC，待处理优先通过状态筛选完成；不假造严重度或最早发生日期排序。跨类型优先级/时间排序属于 R6 |
| 筛选/视图 | E 类型、状态；默认待处理，三个系统视图对应三个类型。当前无全类型搜索合同，不显示搜索框；R6 才可补对象搜索 |
| 汇总 | E `openCounts` 分类型展示，只读差异与可办理数量分开；不累计差额形成“损失金额” |
| 批量 | 首期无通用批量解决。合同余额差异只有查看证据，没有“标记已处理/接受全部”。余额待认领与同日冲突只复用各自允许的方法 |
| 状态 | 没有可用账户时指向有权账户维护页；候选金额未加载禁止提交；已被替代/已处理只读；账户关闭或版本冲突保留填写内容，其他按 §3.3 |

详情头显示对象、类型、状态；主体是三栏金额比较（手机竖排）和原始证据。待认领选择有权且有效的目标账户；同日冲突从服务端候选金额中选择。`contract_balance_mismatch` 标注“只读核对”，由 owning Finance 业务入口完成后续处理，不能增加一个前端通用 resolve 动作。

## 8. 数据边界、权限与职责

| 事实/动作 | 所属域与展示边界 |
| --- | --- |
| 客户/联系人、合同主体内容与负责人 | Altoc；复用 owning typed 入口，Finance 页面只通过授权关联读显示，不跨域写 Altoc 表 |
| 法人主体、银行账户、余额登记、当前财务事实 | Finance；Altoc 财务页签调用现有受控读取，不把余额复制成合同的可编辑字段 |
| 原签约额/有效额与当前回款 | 前两者按 Altoc/W1 定义；回款及财务核对归 Finance。同名“金额”必须带口径和来源 |
| 历史余额差异 | 展示源缓存与核对值；不将差异自动计为应收、不用新登记伪造源历史 |
| 用户目录及身份状态 | Foundation/People 的既有入口；APF 选择器过滤只是交互，服务端 owner guard 必须保留 |
| 工作流与审批 | 使用现有 Foundation/Workflow 合同与 app_code 映射；不从历史状态推断审批动作组 |
| 附件与审计 | 各所属域授权只读投影；不把原始迁移台账/任意 URL 直接开放给通用附件页签 |

Manifest 是权限唯一事实源；本方案不新增 capability 或重配角色。用户操作继续走 `<domain>:enterprise-host:execute` 下已登记固定操作及对应 permit。补充读/写操作时同步 Runtime 来源校验、Host 注册和测试；不能把 scheduler/notification-detail 当作页面绕过通道。

共享视图只共享查询定义，不共享结果；owner、金额和关联数量均按当前调用者数据范围返回。`admin` 只蕴含同资源 view/edit；关闭、解密、迁移处理、未来导出等敏感动作独立声明。状态不可办与没有权限要分别解释，但不泄漏受限对象细节。

## 11. 实施验收与设计交接

每批 PR 附独立证据，不以本设计文档等同验收完成：

1. **视觉**：真实浏览器 1440×900 与 390×844，记录页面、身份范围、状态和操作；截图只用合成数据或经脱敏内容。页面整体无横向溢出；表格内滚动可达；弹窗/抽屉、页签、分页、长标题与多币种不遮挡。
