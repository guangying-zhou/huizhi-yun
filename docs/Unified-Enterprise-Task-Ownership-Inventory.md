# ADR-018 后台任务所有权清单（INT-305）

核对日期：2026-09-15。证据为当前工作树源码、自动测试和 INT-001 同一观测窗口的环境回读（[回执](../deploy/test-env/artifacts/C000001.int-001-observation-window.json)）。本文逐任务记录旧 owner、目标 owner、开关、generation、在途 operation、正式 capability 与切换/回退证据；它是 INT-305 的判定依据，不代表任何任务已在环境中切换。

## 1. 环境事实（C000001/test）

- 全环境唯一 cron 是 Gateway 的 `0 16 * * *`，只执行 policy sync；Aims、Assets Worker 均无 trigger。**当前是「零定时 owner」**，所有业务任务都只能经请求驱动或显式触发执行。
- 当时的盘点记录发现 Assets 不在可用的 scheduler wake 交集中。2026-09-24 工作区候选核对：Gateway `SCHEDULER_APPS` 已含 `assets`，缺口实际是 Platform scheduler registry 未上报 Assets，且 Gateway `wrangler.jsonc` 未声明 `HZY_ASSETS_SERVICE`。候选修正已补齐这两处，尚未部署；本节环境观测仍以 2026-09-15 回读为准。
- Aims 的统一存量选择已回读为 `scheduler.storage=unified`、`generation=1`（[Gateway 发布记录](../deploy/test-env/artifacts/C000001.unified-gateway-release.json)）。
- Enterprise Host 的 Layer `tasks=[]`，Host 不注册 `scheduledTasks`（`enterprise/test/registry.test.mjs` 断言）。

## 3. 关闭 INT-305 所需的最小工作

1. 为 Aims 通知、milestone rollover、Assets 交付状态投递与 Assets 通知各自新增 `/v1/enterprise/**` 统一路由，复用 `enterprisescheduler` 的 storage/generation fencing 与 claim/checkpoint 语义；milestone 与 Assets 投递先把宽 scope 收敛为精确 capability，并补 `data-runtime`/`tenant-runtime` 双 audience grant seed/verify。
2. Gateway 把统一任务的唤醒纳入同一签名选择；`assets` 进入 wake 集合前必须有 generation 绑定，避免旧 Worker 与统一 Runtime 双消费。
3. 每个任务补切换与回退测试：unified 选择、disabled 不唤醒 legacy、非法选择失败关闭、恢复选择；在途 operation 在切换点由同一 operation 身份结清。
4. 在目标环境恢复唯一定时 owner 后，同窗回读 trigger、scheduler selection 与 grant，证明每个任务只有一个触发者。

在第 1～3 项完成前，统一切换不得声称已接管后台任务；按 [Runbook](./Unified-Enterprise-Cutover-Runbook.md) 第 5 节记录「零定时 owner」状态。
