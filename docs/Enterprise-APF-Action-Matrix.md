### 1.1 通道和人员判权

除机器行外，U 为 `<domain>:enterprise-host:execute`，由 Enterprise 重新取得服务身份，携验签用户委托、≤15秒 token-bound permit。人员列是 resource:action，**不是服务 capability**；同一行跨域另判权不通过就整体拒绝。所有操作仍保留 owning 核心的范围、状态、版本、回执重放前授权与字段白名单。Finance 的费用确认、开票、核销等专门动作不由 edit 替代。

人员动作取自 [People 主数据](../enterprise/server/utils/enterprisePeople.ts)、[People 事实](../foundation/server/utils/enterprisePeopleFactsPermit.ts)、[Finance 账户参数](../enterprise/server/utils/enterpriseFinance.ts)、[Finance 账务](../enterprise/server/utils/enterpriseFinanceLedger.ts)、[Finance 成本](../enterprise/server/utils/enterpriseFinanceCost.ts)及每行 Altoc helper；对象范围统一用 Foundation evaluator/投影，Runtime 权威复核。

### 5.1 外部效果与附加门槛

- People provisioning 各分支的 Runtime operation 见 §3；投递到 Console 的 reserve/release、provision/status/activation-link 及 employment sync，使用 [固定 Directory 合同](../foundation/server/utils/directoryServiceCommand.ts) 的精确 capability。只认受信 enterprise.runtime，不信任 body 来源。prepare/目标确认/阶段回执不可压成一个通用 action。任职未来生效不得提前投影。
- Altoc contract 项目计划由 Aims owning caller-Tx 处理，每个拟建/关联项目分别签 projects:create/edit 范围；服务工单 dispatch 的 Aims 批量目标在同事务内逐对象预检。表中主资源许可不是跨域授权替代。
- Knowledge link/resume 目标要求 `assets:asset-link:create`、`codocs:knowledge-link:create` 的窄合同及目标用户许可，现有文档/资产才可关联，不创建正文、不隐式分享。正文或数量没有权限不返回。
- Feedback submit/resume 仅原键恢复，产品门槛是 Aims product_requests:create；status/progress 入站保留 Aims 原身份、scope、信封和 owner。Enterprise 只新增接收落点，不迁移 producer。
- Finance invoice-files-attach 还有受控 OSS 写入/版本确认，不能用 Runtime 回执代替存档完成。审批 submit 的 request/bind 是同一冻结意图的分阶段操作，浏览器不能提交批准结果。
