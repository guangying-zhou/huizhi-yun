## 4. 中期优化（P1，一个月内）

1. **数据范围落地**（这是销售/部门线角色真正的差异所在）：
   - sales_specialist：customer/opportunity/quotation → `subject:self`
   - sales_manager：同资源 → `department:self` 或 `department:tree`
   - department_manager：expenses/assets 审批相关 → `department:tree`
   - 项目线不需要配 scope（已由 project:member/owner 动态关系承担）。
2. **职责冲突规则激活**：商务经办/审批、财务制单/审批、采购经办/审批，小企业兼岗现实下建议 `warning` 级（授权时提示不阻断）；发布/部署类保持代码内置 enforce。
3. **新建 4 个模板**：project_qa、product_director、marketing_director、commercial_assistant（§2 映射）；aims manifest 新增 `aims:qa` 应用角色。
4. **C000002（汇房）**：若要启用，按同套模板物化 + 按岗授权；不启用则保持零授权现状即可。

## 5. 治理习惯（持续）

- **最小授权 + 按岗授权**：新员工只授"岗位模板角色"，杜绝"先给个 admin 再说"。
- **多角色合并是常态**：兼岗直接叠加多个岗位角色（merged 模型自动并集），不要造"某某兼岗专用角色"。
- **用角色模拟做验证**：每次调整授权后，用 system_admin 的模拟能力以目标角色视角检查页面（已在生产可用）。
- **季度授权盘点**：核对 tenant_subject_roles 与在职岗位；离职/转岗走 People→Console→Platform 生命周期联动回收。
- **模板为源**：调整岗位权限改模板（或 manifest 推荐角色）再物化下发，不做租户级散改，避免漂移。
