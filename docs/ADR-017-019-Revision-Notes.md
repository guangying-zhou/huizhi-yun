## 2. 保留的原始决策

未推翻“平台提供应用与治理、客户侧 Runtime 承担租户数据与服务”的主线；未恢复 Console/Host 数据库直连、Hyperdrive fallback、中央企业 Session 或平台租户私钥。

保留 Enterprise Host + Nuxt Layers、同租户核心业务单库、受控 JOIN/查询服务/本地事务、业务写入主责、产品链试点、全量功能资格与人员授权区分。

保留 Platform 独立控制面；Codocs/Workflow/Collab/通知/Connector 等首轮独立边界；不纳入 legacy Account。不同企业与不同环境不因合库混用。

保留当前主档、规划关系、接入来源与历史快照的不同语义；不机械删除投影，不统一改主键，不新建 Console 中央业务关系表。

原 ADR-017 的 Accepted 与 ADR-018 的“架构方向已确认”作为原决策状态保留；本次新增条款和 ADR-019 标注为待审阅。没有将文档修改写成代码已迁移、数据库已合并或功能已发布。

## 3. ADR-017 的实质修订

| 原文位置 | 修订后的处理 | 解决的问题 |
| --- | --- | --- |
| §2.1 平台不得持有 | 区分权威持久化、长期秘密、必要协议瞬时转发；纳入 Enterprise Host | 不再一边绝对禁止 Token 经过、一边又要求协议代理 |
| §2.2 调用链 | Host/Console 可同进程组合，但都不直连；不要求新增 HTTP 跳转 | 统一前端不制造第二个必经 BFF |
| §2.3 Console 数据域 | 初期保留客户侧 hzy_console 及安全域访问身份，区分 Directory 与 Auth/Vault | “业务单库”不隐式开放认证/密钥表 |
| §2.4 Auth 下沉 | 不提供任意 payload/subject/scope 签名；引导与日常 workload 分离 | 私钥在客户侧不等于任意签发请求都安全 |
| 新 §2.7 安全目标 | 明确 UI/BFF 可能处理授权明文，不宣称端到端绝对不可见 | 避免过度安全承诺及日志/缓存形成隐性副本 |
| 新 §2.8 信任链 | 明确 bootstrap、workload、用户委托、JIT 与控制面/软件发布信任 | 防止全权限 Host、身份伪造或引导凭证越权 |
| 新 §2.9 故障/恢复 | 按 Runtime/Auth/Platform/DB/IdP 故障分类，覆盖旧备份会话恢复 | 不把离线验签等同于业务可用，不复活旧撤销凭证 |
| 新 §2.10 Host 与任务 | Host 是唯一主 Shell；可靠业务任务有唯一执行责任 | 防止两套 Shell 和重复 cron/Outbox |
| §4 / 新 §8 | 补齐协议兼容、撤销旧权限、独立切换与 SEC-01～08 | 用上线证据而非删代码判断迁移完成 |

## 4. ADR-018 的实质修订

| 原文位置 | 修订后的处理 | 解决的问题 |
| --- | --- | --- |
| §2 / §3 | Enterprise Host 管主 Shell，Console 管协议与基础能力；前端细化交 ADR-019 | 避免两套企业入口争夺会话/导航主责 |
| §3.1 | 区分路由兼容与永久信息架构；增加撤权缓存与迟到响应处理 | 不因保留旧 URL 就永久按应用组织，不因状态复用串租户 |
| §3.2 | 明确 Host 内与 Runtime 内“同进程”的分别范围 | 不误以为 TS Host 能跳过信任边界直接调用 Go 内部方法 |
| §4.1 | 同租户同环境业务库；迁移/连接池/稳定标识与安全域分开管理 | 不把合库当共池、统一 ID 或放开全部表权限 |
| §4.2 / 新 §4.4 | 受控 JOIN 保留，增加数据依赖、对象/字段/汇总与部分可用合同 | 不退回全远程 API，也不让作者各写一套授权逻辑 |
| 新 §4.5 | 同一事务句柄、状态复核、Receipt/Outbox、结果不确定与重试规则 | 防止“函数传了 tx”但实际混用默认连接池 |
| 新 §4.6 | Host 只启动已登记前端/HTTP 副作用，业务任务由主责 Runtime/服务执行 | 不把任务登记等同于全部任务迁入 Host |
| §5 | 全量资格仅针对汇智云自身，不删除租户对外产品版型/价格能力 | 防止商业策略调整误删业务系统功能 |
| §6 / §7 | 分离 Auth/Host/物理合库切换，增加 DDL、hash 资源、整包回退 | 新路径可回退但不恢复旧数据写入事实源 |
| 新 §10 / §11 | 三 ADR 分工与 INT-A01～09 | 补齐从决策到测试的门槛 |

## 5. ADR-019 新增的核心决策

企业前端目标不是 Aims/Assets/Altoc 应用切换器，而是工作台、产品与研发、客户与合同、项目与服务、经营与资源等业务入口；知识/协作和管理按实际能力作为辅助入口。名称和范围作为建议待冻结，不将全部目标功能标记成已实现。

首个产品工作台复用 Assets 产品主档与 Aims 规划/版本；特别区分“产品业务视图”和 Aims“产品管理空间”，不假定一对一。商业与客户区域可以后续扩展，不阻塞当前产品链验收。

合同保留“总览、合同事实、合同执行、合同管理”，事实中区分基本信息、标的、条款与文本，执行中组织履约、结算和回款。不用前端重新解释账务或合同事实。

技术上选择单一 Nuxt Host 的构建时组合；运行时微前端、全面 iframe 化和换框架不作为默认路线。独立编辑器等保留受控接入，真实服务边界继续鉴权。

旧 URL 兼容、类型化目的地、请求级上下文、上下文切换屏障、部分失败和发布回退共同定义“像一个应用”的最低条件。

## 6. 实施顺序与是否依赖合库

| 阶段 | 主要目标 | 是否等待物理合库 |
| --- | --- | --- |
| FE-0 | 盘点、合同、基线和任务责任 | 不等待 |
| FE-1 | 单一 Shell、Aims/Assets UI 提取、旧地址兼容 | 不等待；使用正式 API |
| FE-2 | 产品工作台及产品事实/规划/版本连续体验 | 可以先用正式聚合 API，之后按 ADR-018 替换内部查询 |
| FE-3 | 客户/合同/项目/服务及成本经营链路 | 各用例独立评估，不把整个平台合库作为统一前置 |
| FE-4 | 旧入口/任务/身份清理、性能与辅助能力完善 | 已切换领域完成证据后收口 |

Auth/Vault 迁移与业务单库迁移有独立风险，不与整套前端替换捆绑。安全边界仍必须满足，不存在“因为先做 UI 就可临时关鉴权”的例外。

## 7. 来源与新增建议的边界

项目现状依据仅为两份上传原稿及其明确记载的基线，不等于已读取它们引用的实施台账、全部 API 文档或最新生产配置。原稿没有提供的具体 action code、旧 URL 清单、依赖版本、SLO 和容量数字均未伪造。

本次新增的业务导航、前端目录、五项合同、阶段/验收编号和安全细化属于架构建议。Nuxt/Vue、Cloudflare、Go、MySQL 和 IETF 的引用用于确认技术机制，相关官方来源在各文档中列出，核对日期为 2026-09-15。

未替换 `Unified-Enterprise-Implementation-Plan.md` 或其他未提供文档。技术路线中的 FE 工作包应合并登记到原台账，而不是直接覆盖已有 INT 编号及进度。
