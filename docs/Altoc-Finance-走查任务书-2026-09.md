## 2. 走查范围

### 2.1 Altoc 主线（依据 `docs/user/tenant/09-应用-Altoc经营.md` §9.2）

```text
线索 → 客户 + 商机 → 报价/投标 → 合同 → 合同生效
  → 自动在 Aims 建交付项目并同步里程碑
  → Aims 里程碑验收 → 回款计划推进到「可开票」
```

重点验证**自动编排**是否真的自动——手册声称"这条链是自动打通的，不需要在三个系统里重复录入"，需逐段确认。

### 2.2 Finance 收入侧（依据 `docs/user/tenant/10-应用-Finance财务.md` §10.2）

```text
开票申请（来自 Altoc 回款计划）→ 开票审批 → 正式发票
  → 到账/收款登记 → 核销 → 回写 Altoc 合同财务摘要
```

### 2.3 Finance 支出侧（§10.3）

费用报销 / 项目支出 / 付款申请三条审批链。

**必查职责冲突**：应付会计（`finance:ap_accountant`）制单不付款、出纳（`finance:cashier`）付款不制单。手册明确"配权限时不要合并"——需验证服务端真的拦得住，不只是界面隐藏。

### 2.4 明确不在本次范围

- 进销存、坏账、DSO 等边缘功能（10 月 W2 补走查）
- 前端视觉与响应式细节（除非阻断流程）
- 性能优化
- Altoc 工单入口（10 月 P1，视试点客户诉求再定）

## 3. 重点排查方向

以下四类是 AIMS 那轮**各中过至少一次**的坑，优先照着查：

| 类别 | 具体查什么 | AIMS 踩过的原型 |
| --- | --- | --- |
| **跨应用授权** | 每个跨应用调用是否取了服务令牌、scope 是否精确匹配、`aud`/`source_app`/`target_app` 是否正确 | 立项 401：调 Console Directory 没传 event、没取令牌，还把错误吞成 `null` |
| **标识符语义** | `uid` / `subjectCode` / `externalRef`、合同编码 / `project_code` / `biz_id` 是否被混用 | 质检 403：Console 用 `externalRef` 当 `holders[].uid`，同一个人被判成两个人 |
| **错误映射** | 业务冲突是否被伪装成 5xx；唯一键冲突该 409、参数非法该 400 | 创建项目集 503：MySQL 1062 没映射成 409，被 BFF 兜底转 503 |
| **schema 漂移** | 目标库是否执行了全部 migration；关键扩展表是否在 runtime `requiredTables` 里 | 开始执行 503：生产缺 `work_item_service_ext` 的 v5.4 列 |

另外**必查负向用例**：非授权角色访问列表/详情/导出，确认服务端真的拒绝（不是前端隐藏）。财务金额敏感，这条比功能本身更重要。

## 4. ISSUE 清单格式

输出到 `docs/Altoc-Finance-走查ISSUE清单-2026-09.md`，每条：

```markdown
### ISSUE-B-001 简短标题

- **级别**：P0 / P1
- **模块**：altoc / finance
- **路径**：页面路由或 API
- **现象**：实际发生了什么（含 HTTP 状态码、错误码原文）
- **期望**：应该发生什么
- **复现**：最短复现步骤
- **初判类别**：跨应用授权 / 标识符语义 / 错误映射 / schema 漂移 / 业务逻辑 / 前端
- **证据**：请求响应片段、日志行、截图路径
```

**分级标准：**

- **P0** — 阻断主线：合同无法生效、开票申请发不出、核销做不了、金额算错、非授权角色能看到不该看的数据
- **P1** — 主线能走通但体验差或边缘场景出错
