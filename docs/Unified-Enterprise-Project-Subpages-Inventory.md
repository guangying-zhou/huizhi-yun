## 本批读取路径与授权边界

- Host 页面：`/aims/projects/:id/{metrics,risks,output,releases}`，以及 `output/:deliverableId`、`releases/:releaseId`。`environments` 因实际可写而没有登记。Host 对象导航只列已登记页，导航权限取人员资源 `projects:view`。版本列表/摘要沿用源页的 `releases` 模块开关，未启用时不发版本读取请求。
- API：保留已有 `GET /aims/api/v1/deliverables?project_id=…` 与 `GET /aims/api/v1/projects/:id/releases`；新增 `GET /aims/api/v1/projects/:id/deliverables/:deliverableId`、`GET /aims/api/v1/projects/:id/releases/:releaseId`。这两个详情 API 使用现有 Runtime `:list`，单次调用取受项目范围约束的数据后只返回精确 ID。不存在或不可见为 404，非法 ID/筛选参数为 400。
- `enterpriseAimsDeliverables.ts` 在 `prepareEnterpriseRuntime` 前取得 Foundation 授权快照并调用 `authorizationResourcesAllow(resources, 'projects', 'view', actionPolicies?.projects)`；缺权 403，无 Runtime 调用；授权依赖 503 原样传递。签发的服务许可仍是 `project-deliverables:view` / `project-releases:view`，actor/tenant/deployment 来自可信 Enterprise 会话，项目数据范围由 `enterpriseAimsProjectScope` 生成。没有新 grant、seed 或 Runtime 授权改动。

## 范围说明

本批 output 的“详情”是现有交付物列表返回的完整元数据行；未打开文档内容或质量审批细节。本批 releases 的“详情”只含列表已有的版本摘要，不含原页的特性、工作项、日志；完整详情以提议 1 为后续条件。源页上的仓库、产品关联、审批和发布写入口均未在 Host 专页暴露。

## 后批分页

交付物与项目版本的原页、Runtime 当前均按项目读取全量列表，本批保持相同行为。后续写动作批次连同 Runtime 列表契约补服务端分页和总数，BFF 严格校验 `page` / `pageSize` 并保留项目可见性过滤，Host 列表再接 `UPagination`；版本摘要详情仍须精确校验项目及版本 ID，不依赖列表当前页。W1-A2 不实施分页。
