# ADR-020：基于 ygo 的 Collab Go 化与 Connector Runtime 模块化整合

状态：**Deferred（优先方向已记录，实施延期）**。

日期：2026-09-22。版本：1.0。

决策性质：将“基于 `reearth/ygo`，把 Collab 作为 Go 模块整合进 Connector Runtime”确定为后续优先验证路线；**不是立即采用某一 ygo 版本，不是生产发布批准，也不声明已具备兼容性、数据迁移或性能验收证据。**

决策范围：协作引擎选型方向、Connector 内嵌方式、Enterprise／Connector／Data Runtime 职责、协作协议与授权、内容持久化、正文转换、运行隔离、延期实施门槛，以及旧 Collab 迁移与回退。

## 1. 背景与决策动因

汇智云正在将普通企业业务页面和薄 BFF 收敛到 Enterprise，业务权威状态及事务由客户侧 Data Runtime 承担。Codocs 保留文档领域职责，但不以长期保留完整独立企业前端为目标；实时协作等能力可以有专门运行位置，不要求保留第二套菜单、应用外壳和会话体验。[P1][P2][P3]

用户已说明，Connector Runtime 与 Data Runtime 分开部署的重要原因，是企业微信等外部连接需要稳定的域名／IP，并需要控制不同负载之间的影响。新增协作能力不能破坏这个初衷。

上一轮讨论首先考虑将 Node.js＋Hocuspocus Collab 作为 Connector 套件中的独立进程交付。该方式可以复用现有实现，但私有部署仍需管理 Node 运行环境和独立协作进程。`reearth/ygo` 提供了纯 Go 的 Yjs 实现及可嵌入 WebSocket 服务，使“直接复用 Go 协作引擎，而非自行重写 CRDT”成为新的候选。[Y1][H1][H2]

本次要减少的是**部署、依赖和运行适配复杂度**，不是取消文档权限、权威版本、审计或可靠保存要求。Go 实现是否在本项目中更快、更省内存、更稳定，仍需测量，本文不作性能结论。

## 2. 决策摘要

| 编号  | 决策  |
| --- | --- |
| D01 | 将 **ygo＋汇智云适配层＋Connector 内嵌 Collab 模块**作为后续优先验证路线；当前延期，不自动进入开发或试点。 |
| D02 | Enterprise 继续提供同一套文档工作区、Milkdown 编辑器和浏览器 Yjs 客户端；不为 ygo 另建企业应用或第二套文档前端。 |
| D03 | ygo 负责协作数据结构、同步和相关服务端机制；Connector 负责受控协作执行；Data Runtime 保留文档 ACL、正式版本、当前引用、generation／epoch、事务和审计主责。 |
| D04 | 以可编译进 Connector 的 Go 模块为目标。普通规模部署在共同负载验收通过后可同进程运行；需要故障或权限隔离时，允许同一模块／产物以独立进程运行，不维护第二份协作业务实现。 |
| D05 | 必须补齐四类适配：**授权先于数据暴露、房间与协议映射、正文转换等价、可靠持久化与正式提交确认**。不得把协议兼容声明当成免适配依据。 |
| D06 | Connector／Collab 不直连企业业务库或安全域库。协作内容通过获准存储适配处理，正式元数据变更通过 Data Runtime 类型化接口提交。 |
| D07 | 复用并完善现有文档写入协调合同，不另建平行的保存、版本或回执系统。引擎替换不得绕过尚未完成的写入协调与授权前置条件。 |
| D08 | 当前 Cloudflare Collab 和已有 Hocuspocus 路径继续按既有合同运行。只有在等价性、故障恢复及迁移验证通过后，才按获准范围切换；禁止同一文档在独立新旧房间同时接受真实编辑。 |
| D09 | 首批未来验证限定单实例、既有文档类型和有限数据样本。不同时引入 Redis 集群、全量文件转换平台、编辑器重写、数据库合并或 VPC。 |

“优先验证路线”不等于无条件采用 ygo。若关键兼容性、安全性或保存保证无法在合理成本内达到要求，保留现有实现并修订选型结论，不以降低权限或一致性要求换取部署数量减少。

### 3.2 上游提供的能力与仍待验证的差距

上游 README 说明 ygo 提供纯 Go Yjs 实现、V1／V2 二进制更新、XML 等共享类型、同步与 Awareness、Hocuspocus 相关协议、`net/http` Handler、持久化扩展和运行资源限制，并说明其一致性测试使用固定 JavaScript Yjs 基准。[Y1][Y2]

这些是上游资料和接口依据；“production-grade”等评价不视为汇智云的验收结论。本文未证明所有 Milkdown 自定义节点、历史文档、权限状态或保存行为已兼容。

| 已核查的基线行为 | 对本项目的含义 |
| --- | --- |
| ygo 帧内 `OnTokenAuth` 不是文档保密性准入屏障，初始同步可能先于认证拒绝。[Y2] | 不能只迁移 Token 校验函数；必须保证未授权连接不能收取正文或提交更新。 |
| ygo 默认从 `room` 路由参数或 URL 最后一段取房间；Hocuspocus framing 需显式启用。[Y2] | 固定 `/codocs/ws` 加参数的现有调用需要明确适配。 |
| ygo 在已检查实现中对帧内文档名不匹配记录日志后继续处理。[Y3] | 获准文档、内部房间及帧名的严格一致性由适配层补齐。 |
| `StoreUpdate` 消费增量更新；默认存在批量合并与延迟持久化。[Y2][Y4] | 不能覆盖写最后一个增量，也不能以同步完成代表持久化成功。 |
| 汇智云使用自有 Hocuspocus 协议客户端，具有特定事件、认证帧和重连行为。[H3][H4] | 应验证真实客户端，不只运行上游示例。 |
| 当前协作链还包含 Yjs 到正文／Markdown 的转换。[H5] | Go 协作引擎不能自动替代文档转换与预览／导出语义。 |

未来执行时，应重新核对这些行为是否已由上游修复或改变；保留本项目的契约要求，避免重复修补已解决的问题，也不得沿用过期假设。

## 4. 目标结构与职责边界

```text
Enterprise：统一文档界面、Milkdown、浏览器 Yjs 客户端
    │
    ├── 正式业务 API ────────────────────────────┐
    │                                           │
    └── 获准的协作 WebSocket                     │
             │                                  │
             ▼                                  ▼
Connector Runtime                          Data Runtime
    ├─ 原外部连接模块                         ├─ 文档 ACL／状态
    │   企业微信／钉钉、通知、同步              ├─ 正式版本与配对引用
    └─ Collab Go 模块                         ├─ generation／epoch
         ├─ 连接准入与房间适配                 ├─ 候选、提交、回执、审计
         ├─ ygo CRDT／同步引擎                 └─ 企业业务／安全域数据库
         ├─ 持久化与正文转换适配
         └─ 正式文档客户端 ────────────────────▲
             │
             └── 获准对象存储：更新、快照、正文等
```

图示为目标职责，不表示接口已经实现，也不要求所有箭头都通过同一个公网域名。入口代理可以直接把协作路径送到 Collab Handler，不必先绕行一次外部连接业务接口。

| 能力／数据 | 权威责任与目标位置 |
| --- | --- |
| 文档列表、编辑器、保存状态、来源返回 | Enterprise；尽量复用原界面与客户端。 |
| 房间中的实时 CRDT 状态、连接、同步、在线状态 | Connector 内的 Collab；受已验证的文档权限和写入代次限制。 |
| 文档归属、ACL、冻结／删除／发布状态 | Data Runtime 文档领域；不能复制成 Connector 的另一套权限主档。 |
| 正式正文／Yjs 引用、文档版本、提交回执 | Data Runtime 按既有写入协调合同原子发布。 |
| 二进制更新、候选快照、正文文件 | 获准存储；其归属、可读状态、保留和清理由正式合同约束。 |
| 当前 OIDC／Vault／服务签发权威 | 继续遵循 ADR-017，不随协作 Go 化迁到 Enterprise 或一般 Connector 业务模块。 |
| 企业微信等连接与执行账本 | 保持原 Connector 主责，不因增加 Collab 改变其业务语义。 |
| 大型文件转换 | 专用受限执行器的后续事项；不默认嵌入 Connector 主进程。 |

Connector 的本地投递账本与“企业业务数据库”须区分。若未来需要新增本地协作更新日志，其持久性、企业内容归属、加密、备份、空间上限和恢复责任必须明确批准；不能把唯一协作数据当作可随意清理的缓存。ygo 提供某种数据库适配，不等于本项目批准 Connector 直连企业 SQL 库。[Y4][P1]

## 5. 协议、身份与房间适配

### 5.1 授权先于内容暴露及写入

必须在加载／发送任何受保护文档状态、房间在线信息或接受更新之前，完成连接准入。仅设置 `OnTokenAuth`，或仅检查浏览器 Origin，均不能构成完整准入。

未来可在以下实现方式中选择其一，并记录精确契约：通过 HTTP／WebSocket 升级边界验证文档绑定的受控准入凭据；或实现严格的帧内预认证状态机，在通过认证前禁止文档同步和写入。本文不把其中一种机制冒充现有实现。

采用 `AuthFunc`／`Authorize` 与 `OnTokenAuth` 组合时，后者不能扩大前者已经限定的权限。若两个判断不一致，应拒绝或使用更严格的范围，禁止只读在后续认证中变为可写。[Y2][Y3]

连接身份至少绑定适用的 tenant、environment、deployment、正式文档引用、subject、读写权限、目标 audience、有效期和协作 epoch／写入代次。具体字段名沿用正式身份合同；浏览器提供的 `uid`、`name`、`doc`、`documentName` 只作为待验证输入，不能自行建立权威身份。

WebSocket 准入不以平台超级 Token、永久共享 Secret 或业务数据库凭据实现。若浏览器连接方式需要短期票据，应单独约束文档、用途、有效期、重放和日志处理；不得把通用 Access Token 放进可记录、可分享的 URL。新身份能力必须通过正式登记、精确授权和撤销机制接入，不自动继承 Connector 全部权限。

### 5.2 连接建立后的权限变化

撤销分享、撤销编辑权、主体退出、文档冻结／删除、版本恢复和 epoch 变化必须影响已建立连接。准入租约的最长有效时间和检查方式在未来合同冻结；不能让一次成功握手获得无限期编辑权。

Data Runtime 暂不可用时，按正式授权有效期与实时校验要求处理：不能签发新的准入或伪造提交成功；要求当前权限才能继续的操作失败关闭。任何暂存编辑都应有上限和明确的未持久化提示，而不是无限离线接收。

服务端注入、自动修改以及 Stateless 等旁路也受权限约束。不得把 ygo 的 `Apply`、`BroadcastUpdate` 或可变文档句柄公开成任意写入接口；技术 CRDT client ID／Awareness 姓名不能作为可信审计身份。[Y1][Y3]

### 5.3 房间标识与客户端协议

现有客户端采用公共协作地址、文档参数及带 `doc:<uuid>` 的 Hocuspocus 帧，且当前是一份 provider 管理一个文档。[H3][H4]

适配层必须统一以下映射：

```text
正式验证的租户／环境／部署 + 文档 + 活动协作代次
    → 唯一获准的内部房间
    → 兼容的客户端文档名和消息帧
```

不得把固定路径 `/codocs/ws` 的最后一段 `ws` 当成所有文档共用的房间，也不得仅靠全局 UUID 或浏览器自报租户分房间。房间、存储键、路由、认证票据及消息帧引用必须一致；名称编码、大小写和路径规范化应只有一套规则。

启用 ygo 的 Hocuspocus framing 后，仍需验证认证帧、同步请求／回应、只读行为、Awareness、关闭码、重连和事件语义。当前已检查实现不提供完整多文档连接复用；首批沿用单连接单文档，不承诺未验证的协议扩展。[Y2][Y3]

## 6. 内容持久化与正式保存

### 6.1 复用既有写入协调合同

优先消费并完善 `Codocs-Document-Write-Coordination.md`，不另建一套 generation、候选表、版本表或保存回执。

该合同在本次核对版本中已明确“先存候选，再原子发布引用”、正文／Yjs 配对、普通编辑与活动协作的 epoch 协调，以及历史兼容读取；同时明确部分内部事务／读取能力与正式路由、存储 verifier、Host／Collab 消费尚未全部接通。**本文不会把这些文档中的局部完成说明扩大为正式保存链已可用，也不让 Collab 冒用 `enterprise.runtime` 身份。**[P4]

> 2026-09-24 更新：该合同此后已推进。阶段 A（Host 私人文档 v2 保存、精确读取、派生镜像、v1 写入口互斥）已在 hzy0 端到端实测；阶段 B 的 Runtime 侧已实现并默认关闭，包括协作会话与普通保存互斥、专用服务身份 `collab.runtime`（精确能力 `codocs:collaboration-snapshots:read/publish`）、经会话的 Markdown/Yjs 配对发布，以及共享变更推进 epoch 并撤销会话。阶段 B 同时采纳本 ADR §5.1（一次性准入票据，不用长期共享密钥）、§5.2（续租失败即断开）与 §6.4（记录已验证参与者）。这些 Runtime 合同与协作引擎无关，将来 ygo/Connector 模块应复用，不另建身份或保存路径。

未来 Collab 应按获准的专用身份和正式接口接入这份合同；接口若未就绪，应列为实现前置条件，而不是回退到直接修改对象 key 或数据库。

### 6.2 三种确认不得混淆

| 状态  | 能证明什么 | 不能证明什么 |
| --- | --- | --- |
| 已同步 | 相关更新已在当前协作连接／房间传播或合并。 | 更新已可靠存储；正式版本已提交。 |
| 协作更新已持久化 | 指定更新集合已进入已确认的可靠存储，可按合同恢复。 | Data Runtime 已发布相应文档版本与正文引用。 |
| 正式保存已确认 | 覆盖本次待保存编辑的内容引用与版本已由 Data Runtime 提交，并可重放回执。 | 未包含在该确认中的后续编辑也已保存。 |

前端“已保存”必须绑定覆盖相应编辑状态的确认；确认范围应包含删除等更新，不能只以连接在线、同步事件或一个不能覆盖全部变更的计数判断。

### 6.3 存储适配规则

`LoadDoc` 返回完整可恢复状态；`StoreUpdate` 的输入是增量更新。应正确追加更新或生成一致快照，禁止用最后一个增量覆盖完整 `.yjs` 对象。[Y2][Y4]

已检查 ygo 基线默认合并写入，并有约 2 秒 debounce、默认最长等待 10 秒的配置。这是上游机制，不是汇智云承诺可丢失 10 秒数据。错误重试、关闭刷写和模式差异应对选定版本逐项核验，不能假定上游日志或 hook 自然提供端到端可靠保存。[Y2][Y4]

适配应具备有界积压、错误传播、可恢复重试、操作去重和持久化确认。读取错误或损坏状态不得伪装成空文档；存储不可用时不得开放看似正常的编辑并一直提示保存成功。

### 6.4 目标提交链

沿用既有合同，目标链为：

```text
确认获准文档与当前 generation／epoch
    → 准备绑定命令身份的候选
    → 从同一编辑状态生成配对 Yjs／正文
    → 上传到获准的隔离候选对象／精确版本
    → 在 SQL 事务外验证对象归属、长度与摘要
    → Data Runtime 事务中重验权限、代次并发布引用
    → 写入版本事实、审计和幂等回执
    → 返回覆盖本次保存的正式确认
```

对象上传与 SQL 提交不是同一个可自动回滚的事务。上传后提交失败，不得覆盖当前引用或回写旧正文“补偿”；提交成功但响应丢失，查询／重放原回执，不生成第二次正式版本，不再次写已发布对象。[P4]

普通保存、协作自动保存、导入和恢复必须使用一致的协调规则。合法空文档不应自动恢复旧内容。**引擎迁移保留已有 Yjs 历史；用户明确的普通覆盖／导入／恢复则按既有合同失效旧 epoch、建立新历史，不把这两类动作混为一谈。**

ygo 的技术快照或自动版本功能，不直接成为第二套面向用户的文档版本历史。批量协作提交的执行身份、参与者与审计范围应由正式合同定义，不能把最后一个在线用户当成全部编辑的作者。

## 7. 正文转换与功能等价

复用现有 Enterprise／Codocs 页面、Milkdown 和浏览器 Yjs；协作后端更换不要求重写编辑器或同时升级前端依赖。

现有 `yjsDocumentToMarkdown()` 涉及 `content` 文本镜像与 `prosemirror` XML 结构的转换。[H5] ygo 解决 CRDT 与协议机制，不自动提供汇智云全部 Markdown、预览、导出、批注或自定义节点的业务行为。

未来实现可以移植必要的转换逻辑到 Go，也可以在明确边界内暂用受限转换组件；选定方案须进入依赖清单。不能为了宣称“完全去掉 Node”，静默降低正文或导出质量。

等价性样本应包含当前真正使用的标题、段落、标记、链接、列表、表格、代码块、图片／附件引用、中文输入、特殊字符和自定义节点；批注、锚点及版本恢复按已有支持范围验证。比较文档结构、内容、继续编辑后的收敛和业务输出，不仅比较某次序列化字节。

不支持的文档类型或协议特性应保持原正式去向或明确不启用，不得把失败静默降级为纯文本重建。

## 8. 部署与运行隔离

### 8.1 一个实现，两种进程组织

目标为同一 Go 模块与兼容产物：标准模式可内嵌 Connector；强隔离或高负载模式可单独运行 Collab，继续共用协议、存储与业务适配代码。**是否默认同进程，必须以共同负载和故障测试作出决定，而非只依据企业人数。**

同进程意味着共享内存、GC、崩溃和升级影响，也不能提供对进程内代码的强凭据隔离。模块级独立身份可以限制正常调用，但不等同于独立 OS 账号／容器的安全隔离。需要强隔离时应拆进程，而不是把 goroutine 当作隔离边界。

当前 Connector 的发布脚本仍从 `notification-runtime` 模块中的 `cmd/hzy-connector-runtime` 构建 Go 产物，`connector-runtime/` 承载相应发布与安装组织。[H1] 未来应沿实际入口接入；新增目录、启动参数、模块名和配置字段均待实现设计冻结，不在此伪造现成命令。

### 8.2 运行约束

保留企业微信／钉钉连接所需的稳定域名、出口与回调，不因协作模块接入擅自迁移。协作入口仅暴露已登记的 WebSocket 和必要接口，禁止通用代理、任意存储路径或任意服务端文档注入。

显式配置连接数、房间数、单文档状态规模、消息大小、更新速率、待持久化队列与闲置房间上限。ygo 已提供部分限制，但默认值不等于本项目安全预算；还应控制解码／合并放大后的资源占用。[Y2]

首批单实例，不默认引入 Redis；不得用增加进程副本代替房间一致性和持久化协调。文件转换仍作为后续隔离执行器事项，不混入协作主循环。

健康检查区分进程存活、依赖就绪及持久化可用。日志以稳定错误阶段和关联标识定位问题，不输出 Token、Cookie、签名票据、存储秘密或正文。

### 8.3 发布与关闭

未来发布清单同时记录 Connector／Collab 源码、ygo 精确版本与校验值、客户端协议、存储格式、Data Runtime API／schema 和授权目录兼容范围。

升级先停止新准入，处理在途编辑，确认待持久化和待提交内容，再关闭房间与进程；客户端按合同重连。自动更新器不得在存在未处理写入时无条件退出进程。同进程模式下，应评估一次协作升级会同时影响原外部连接服务的代价。

任何关闭超时或保存未知状态必须可定位、可恢复，不得仅输出成功退出日志。实际关闭、强制终止和恢复行为属于后续验收项目。

## 9. 备选方案与取舍

| 方案  | 优点  | 代价／限制 | 当前决定 |
| --- | --- | --- | --- |
| Cloudflare Collab 保持不变 | 无立即迁移风险，继续使用既有路径。 | 不直接形成纯企业侧 Go 部署；仍需维护平台运行适配。 | 当前继续运行，不提前退役。 |
| Node／Hocuspocus 作为 Connector 套件子服务 | 复用既有服务端与扩展较多，短期接线成本较低。 | 仍需 Node 依赖和进程管理；不能自动解决保存协调问题。 | 保留基线与必要兼容，不作为唯一长期路线。 |
| ygo 编译进 Connector | 与 Go 交付一致，可减少协作运行环境与部署组件。 | 需完成协议、授权、内容转换、保存及共同负载验证。 | 后续优先候选，本次延期。 |
| ygo 同一模块独立进程 | 保留 Go 统一实现，同时隔离生命周期与资源。 | 比同进程多一个服务实例。 | 作为相同实现的部署选项，按证据启用。 |
| 自研 Go CRDT，或嵌入 V8 执行原 Node 服务 | 可自行控制实现。 | 引擎与运行环境维护范围显著扩大，不符合本轮减少复杂度目标。 | 不作为本 ADR 默认路线。 |

收益是潜在的交付收敛，不是“少一个进程就必然更好”。采用后会新增 Go 适配维护、上游升级回归与协作数据迁移责任；应将这些成本与继续使用现有实现的成本一起评估。

## 10. 延期实施与未来阶段门槛

### 10.1 当前状态

当前仅形成并归档本 ADR。**不增加 ygo 生产依赖，不实现或部署概念验证，不改变公共路由，不创建服务客户端或 grant，不变更对象存储／数据库，不关闭旧 Worker，不启动批量迁移。** 注：写入协调合同阶段 B 为现有 Node Collab 建立的 `collab.runtime` 服务身份与协作会话合同不属于本 ADR 的 ygo 实施，与引擎无关，将来由 ygo 模块复用。

不停止现有协作安全维护，也不因未来替换计划推迟当前文档读写、授权和统一前端的必要修复。本 ADR 不作为 ADR-017／018／019 当前阶段或本机测试环境的新增验收阻塞。

## 12. 迁移、回退与旧路径退役

### 12.1 区分新部署和既有协作状态迁移

新企业从零使用 ygo，仍需通过安全、保存和运行验收；已有云端／Node 文档迁入时，另外需要迁移协作状态。

已核查 Cloudflare 实现使用 DO storage 保存 Yjs snapshot；Node 实现使用对象存储保存协作快照和正文。[H2][H6] 修改 WebSocket 地址不会自动搬迁这些状态。必须盘点实际部署的数据位置，不能仅从源码默认值推断线上存储。

### 12.2 受控切换

以批准的租户／环境／文档组为单位：冻结旧准入与写入，处理活动连接及待确认编辑，取得最终可靠状态；导出 Yjs 更新／完整状态和必要业务映射；校验并导入目标存储；验证内容、继续编辑与正式引用；再切换受控路由和协作 epoch，开放新写入。

保留文档身份、业务版本、配对内容、审核／发布状态、generation／epoch、审计、操作回执及适用消费水位。导入工具必须受权、可核对、可重复执行，不提供不受控的房间写入或全桶导出接口。

旧离线客户端、旧 Token 和旧进程恢复时，不得重新成为可提交的 writer。客户端未发送或未确认的编辑需要明确的保留、重新授权和用户处理策略；不能承诺自动合并所有历史恢复与撤权后的修改。

### 12.3 回退

新侧尚无新增写入时，可在验证旧状态与权限后受控退回旧路径。已有新写入后，优先回退兼容程序并继续消费当前权威状态；必须回到旧 provider 时，先围栏新写入、导出并迁回新增状态、核验兼容，再切换。

禁止把自动切回旧 DO 房间或旧 OSS 快照作为高可用方案；禁止两边同时接受真实编辑做“影子对比”；禁止以恢复迁移前数据库备份覆盖新增事实。无法证明安全回退时应进入受控只读／恢复流程，不制造第二写入源。[P2][P4]

### 12.4 退役条件

只有对应页面、服务调用、房间、后台任务、回调、旧客户端及静态资源的消费者均已处理，兼容窗口结束，恢复演练通过，才逐项删除旧 Collab 部署与专用授权。不能因为新的两个浏览器已经互通，就停掉所有 Codocs／Collab Worker。

## 13. 与现有 ADR 和工作计划的关系

本 ADR 对 ADR-018 中“首轮保留 Collab／Connector 运行边界”的长期演进方向作专项补充；**在未来批准的迁移范围之外，原合同继续有效**。它不立即废止当前部署边界，也不改写原 ADR 的阶段完成状态。

ADR-017 的客户侧数据与长期秘密边界继续有效。ADR-019 的统一企业前端继续推进，编辑器原生整合与协作后端更换分批进行，不相互捆绑发布。

文档保存首先服从现有写入协调合同。若未来 ygo 适配要求改变其身份、epoch、候选、版本或读取语义，应同步评审该合同，而不是在 Connector 内另做一套私有规则。

本次不修订 Workflow 引擎归属，不迁移全部文件服务，不重命名整个 Connector 仓库，也不把 VPC、全量合库或全量 Auth 迁移列为协作试点的新增必做事项。
