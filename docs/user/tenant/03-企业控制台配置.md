# 03 企业控制台配置

**读者**：企业控制台管理员。
**入口**：企业控制台 Console。

企业控制台是企业内部的配置中心：组织怎么组、员工怎么登录、外部系统怎么连、密钥放在哪。所有业务应用共用这里的配置，配一次就够。

## 3.1 菜单结构

| 菜单 | 路径 | 内容 |
| --- | --- | --- |
| 管理概览 | `/admin` | 控制台首页 |
| 企业资料 | `/org-profile` | 企业基本信息 |
| 目录管理 | `/directory/*` | 部门、委员会、用户、代码仓库、目录源、目录同步 → [04](./04-组织目录管理.md) |
| 系统参数 | `/system-settings` | 运行时、审批流、认证、通知、界面等参数 |
| 节假日管理 | `/work-calendar` | 工作日历 |
| 集成中心 | `/integrations` | GitLab、AI、企业微信、钉钉、OSS 等外部系统 |
| 运行时管理 | `/data-runtime`、`/connector-runtime` | 数据运行时、企业连接运行时 |
| 凭证库 | `/vault` | 密钥与凭证集中存放 |
| 服务凭证 | `/service-clients` | 应用之间调用用的凭据 |
| 系统管理 | `/admin/*` | 日志管理、业务领域、区域管理、应用运行管理 |

看不到某个菜单说明你的角色没有对应权限。企业控制台的角色包括：`console:viewer`（只读）、`console:operator`（运维）、`console:directory_manager`（目录管理员）、`console:directory_operator`（目录基础数据）、`console:security_admin`（安全管理员）、`console:admin`（控制台管理员）。

## 3.2 企业资料

`/org-profile` 维护企业基本信息：企业名称、简称、logo、行业、联系方式等。

这些信息会出现在各应用的界面、导出的文档和对外通知里，填规范一点。

## 3.3 系统参数

`/system-settings` 是全企业的参数中心，按分类组织：

| 分类 | 管什么 |
| --- | --- |
| 运行时 | 应用运行相关参数 |
| 审批流 | 审批流程的默认行为 |
| 认证 | 登录与会话相关 |
| 通知 | 通知渠道与策略 |
| 界面 | 界面显示偏好 |
| 应用参数 | 各业务应用的专用参数 |
| 通用 | 其他 |

顶部可以按分类筛选。修改后逐项保存，保存成功会有提示。

**改参数前**先确认影响范围：认证类参数改错会导致全员登录异常，审批流参数改错会影响进行中的流程。重要参数改动建议先在测试环境验证，或先与汇智云支持确认。

## 3.4 节假日管理

`/work-calendar` 维护企业工作日历：法定节假日、调休、公司自定的休息日。

**为什么重要**：Aims 的工期计算、项目排期，People 的考勤口径、成本快照，Workflow 的审批时限，都依赖这份日历。年初一次性把全年节假日配好，能省掉一年的麻烦。

## 3.5 集成中心

`/integrations` 配置与外部系统的连接。当前支持：

| 集成 | 用途 |
| --- | --- |
| **GitLab** | 代码仓库同步。配默认分支、同步根群组。给 Aims、Insights、Codocs 提供代码数据 |
| **AI Provider** | AI 能力接入。配默认模型、检查路径 |
| **企业微信** | 登录、通知、通讯录。配 Corp ID、Agent ID |
| **钉钉** | 单一入口管理通知、People 数据和单点登录。在“通知与 People”页签配 Client ID（原 AppKey）、Agent ID、Corp ID；Robot Code 默认使用 Client ID，无需重复填写 |
| **OSS / 存储** | 文件与附件存储 |

**配置流程**：

1. 填写基础信息（Corp ID、AppKey 这类**非密**参数）。
2. 保存集成。
3. 到**凭证库**创建对应的密钥（Secret），再回来把凭证绑定到这个集成。
4. 点连通性检查，确认能连上。

> 顺序不能颠倒：没保存集成就绑不了凭证，没有 Secret Code 也绑不了。

**密钥不要直接填在集成参数里**——它们属于凭证库。钉钉集成支持发测试消息，配完可以发一条验证。

钉钉的“登录”页签默认选择**复用当前钉钉应用**，登录、通知和 People 共用同一套 Client ID 与 Client Secret。只有登录回调、权限或发布周期需要隔离时，才选择“使用独立登录应用”；独立应用的 OAuth Client ID 应为 `ding...` 开头的 Client ID / AppKey，不要填写数字 AgentId。

## 3.6 凭证库

`/vault` 集中存放企业的密钥与凭证，供集成和服务安全引用。

**原则：**

- 所有 secret 都进凭证库，不要散落在各应用的配置文件或环境变量里。
- 凭证按用途分类存放，命名要能看出是给谁用的。
- 凭证支持版本管理，轮换时创建新版本而不是覆盖旧版本。
- 只有安全管理员（`console:security_admin`）和控制台管理员（`console:admin`）能治理凭证库。

**轮换外部密钥的标准动作**：在外部系统生成新密钥 → 在凭证库创建新版本 → 集成切换到新版本 → 连通性检查通过 → 停用旧版本。

## 3.7 服务凭证

`/service-clients` 管理应用之间互相调用时用的凭据。

例如 Altoc 要调 Aims 创建交付项目、Finance 要读 Altoc 合同摘要，都通过服务凭证授权。

**日常不需要频繁改动**。需要关注的情况：

- 上线新应用或启用新的跨应用功能时，可能需要新增授权
- 日志里出现"权限不足 / scope 不足"时，多半是这里的授权没配全
- 凭证到期前要轮换

出现跨应用调用失败时，把具体错误信息给汇智云支持，不要自己删授权项"试试看"。

## 3.8 运行时管理

**数据运行时** `/data-runtime` — 业务数据的读写通道。展示 runtime 编码、状态和健康信息。需要 `data_runtime:view` 权限才能看。

**企业连接运行时** `/connector-runtime` — 部署在企业侧、连接企业微信/钉钉/People 的组件。

> 连接运行时**只执行已注册的企业微信、钉钉和 People 能力，不接受任意 URL、方法、请求头或脚本**。这是安全设计，不是功能限制。

安装连接运行时前提：
- 已在 Console 配置发布公钥（trust anchor）；未建立独立 Ed25519 trust anchor 时不会生成安装指令。
- 若连接运行时与数据运行时分机部署，必须先在"数据运行时"页面配置 HTTPS origin——安装指令不会默认回退到本机地址。

这两页偏技术，通常由 IT 或汇智云实施同事操作。

## 3.9 系统管理

| 页面 | 用途 |
| --- | --- |
| 日志管理 `/admin/logs` | 查看企业内的操作日志，排查"谁改了什么" |
| 业务领域 `/admin/business-domains` | 维护企业的业务领域划分 |
| 区域管理 `/admin/regions` | 维护地域划分 |
| 应用运行管理 `/admin/runtime-apps` | 查看各应用的运行状态 |

## 3.10 配置检查清单（新企业上线）

- [ ] 企业资料填写完整
- [ ] 组织架构已建（见 [04](./04-组织目录管理.md)）
- [ ] 全年节假日已配置
- [ ] 员工登录方式已确定并验证
- [ ] 需要的集成已配置并通过连通性检查
- [ ] 所有 secret 都在凭证库，没有散落在别处
- [ ] 角色与权限已分配（见 [05](./05-角色与权限管理.md)）
- [ ] 抽 2~3 名不同岗位的员工实际登录验证一遍
