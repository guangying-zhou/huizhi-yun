# 12 People 人员

**做什么**：员工事实、任职记录、成本快照、绩效周期。
**谁在用**：HR、部门负责人、员工自助。
**状态**：🟡 开发中（Phase 3 MVP），部分功能可能与描述有出入。

> People **不是完整 HRM**。它不做招聘、薪酬发放、社保个税、考勤排班。它做的是"人的事实"和"人的投入产出"，服务于项目成本核算和绩效。

## 12.1 菜单结构

| 菜单 | 内容 |
| --- | --- |
| **工作台** | 人员概览 |
| **员工** | 员工档案与事实 |
| **任职变更** | 入职、转岗、调级、离职记录 |
| **离职交接** | 离职交接任务与资产回收协调 |
| **职级设置** | M/P 序列的职级工资、绩效工资范围 |
| **成本快照** | 月度人员成本快照 |
| **绩效周期** | 个人绩效周期与结果 |
| **设置** | 岗位字典、职级字典、跨应用操作 |

## 12.2 People 与组织目录的分工

这是最容易混淆的地方：

| | 企业控制台的目录 | People |
| --- | --- | --- |
| 管什么 | 账号、登录、部门归属、权限主体 | 员工档案、任职历史、成本、绩效 |
| 谁在用 | IT / 控制台管理员 | HR / 部门负责人 |
| 举例 | 张三能不能登录、属于哪个部门 | 张三什么时候入职、职级是什么、这个月成本多少 |

**正常运营期，入转调离先写 People**，再由 People 把结果投影到组织目录。如果配置了钉钉作为 HR 事实源，钉钉的变更也先写 People。

**离职必须有明确的离职事实和最后工作日**——不能靠"通讯录里查不到这个人了"来推断。

## 12.3 主要功能

### 员工档案

维护员工的基础事实：姓名、工号、入职日期、岗位、职级、部门、状态。工号由 People 自动递增分配，首号为 `000`，不采用钉钉工号；HR 首次保存新员工入职资料时即可看到系统分配结果。具有员工管理员权限的 HR 还可以维护私密人事档案，包括身份证号、出生日期、学历、专业、毕业学校和毕业时间；身份证号在页面和接口中只显示掩码。

字段以钉钉为优先事实源：钉钉有值时需在钉钉维护，People 不允许覆盖；钉钉没有值时可在 People 补充。旧 OA `employee.csv` 可从员工列表执行预检和导入，OA 数据作为最后回退，并且入职日期只补空值。合同、社保、个税等材料仍不属于 People 的范围。

导入验证可使用[合成 CSV 样例](../../../people/docs/examples/employee-archive.synthetic.csv)，其中姓名、来源 ID 和钉钉 ID 均为虚构，身份证号和手机号留空。仅在隔离测试环境配置对应测试员工后执行预检，再确认导入；未匹配行应跳过。真实文件由人事负责人在仓库外的受控位置提供，通过员工列表选择文件上传，不依赖仓库内固定路径，不得提交到 Git。本轮原始 `etc/employee.csv` 已按要求从本地删除，未另存副本。

### 任职变更

记录入职、转岗、调级、离职。每条记录有生效日期和审批状态。

**要点：**
- 未来生效的任职变更**不会提前投影**到组织目录。填了 3 月 1 日转岗，2 月里组织目录还是旧部门，这是正确行为。
- 变更需要审批（`people:approver`）。
- 离职记录的最后工作日决定了资产回收和权限回收的时点。

### 离职交接

离职时形成交接任务清单：工作交接、资产归还、文档移交、权限回收。

- 未归还资产会同步给 Assets 形成回收协调任务
- 交接任务到期会给责任人发通知（需要企业开启该功能）

### 职级设置与成本快照

**职级设置**维护 M（管理）/ P（专业）序列的职级工资和绩效工资范围。M/P 序列的数量由企业控制台的系统参数决定。

**成本快照**是月度固化的人员成本，用于项目核算。计算参数（基本工资、福利费率、管理分摊系数、固定资源分摊）由 Finance 维护，People 用这些参数生成快照。

**为什么要快照**：成本参数会变，但历史月份的项目成本不应该跟着变。快照把每个月的口径固定下来。

### 绩效周期

管理个人绩效周期：绩效基础、评分、确认结果。

贡献数据来自 Aims（项目参与、任务、工时），People 只固化快照，不重新计算项目执行事实。

绩效**金额**（提成、奖金的财务口径）在 Finance，不在 People。

## 12.4 跨应用协同

| 方向 | 内容 |
| --- | --- |
| **People → 组织目录** | 任职事实投影为目录用户与部门归属；离职停用账号 |
| **Aims → People** | 项目参与、任务、工时作为贡献来源 |
| **Finance ↔ People** | Finance 提供成本计算参数，People 生成成本快照 |
| **People → Assets** | 离职员工未归还资产的回收协调 |
| **People → Workflow** | 入职、任职变更、成本调整、绩效周期确认审批 |
| **People → Codocs** | 岗位说明、绩效说明、复盘报告（只引用文档标识） |

## 12.5 角色一览

| 角色 | 能做什么 |
| --- | --- |
| `people:viewer` | 查看员工事实、任职、成本快照和绩效周期 |
| `people:employee` | 员工本人查看个人档案、任职记录和绩效周期 |
| `people:department_manager` | 部门负责人查看授权部门内员工、任职和绩效信息 |
| `people:specialist` | 维护员工档案和入转调离记录（不含审批、薪酬成本、系统设置） |
| `people:manager` | 管理全量员工事实和任职记录，查看绩效与成本（不含专业审批、绩效维护、薪酬成本维护） |
| `people:approver` | 承接任职、成本和绩效周期的人事审批 |
| `people:performance_manager` | 维护绩效周期和贡献快照（不含绩效确认审批） |
| `people:compensation_admin` | 维护职级成本口径和成本快照（不含成本调整审批） |
| `people:directory_admin` | 维护员工事实、岗位字典、职级字典和设置 |
| `people:admin` | 维护全部人员事实、字典、成本和绩效周期 |

**普通员工给 `people:employee`**，能看自己的档案就够。
**部门负责人给 `people:department_manager`**，并配上他管理的部门范围。

> 薪酬成本是敏感数据。`people:compensation_admin` 要严格控制人数，并且它**不含**成本调整审批——调整要 `people:approver`。

## 12.6 使用建议

1. **入转调离先在 People 记录。** 直接改组织目录会造成 People 与目录不一致。
2. **离职要有明确的最后工作日。** 它驱动资产回收、权限回收和成本截止。
3. **每月按时生成成本快照。** 漏一个月，项目核算就缺一段。
4. **绩效数据别手工改。** 贡献来自 Aims，改 People 的快照不改源头，下次生成还是原样。
5. **薪酬相关权限从严。** 定期复核 `people:compensation_admin` 的人员名单。
