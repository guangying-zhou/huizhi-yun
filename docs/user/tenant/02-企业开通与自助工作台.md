# 02 企业开通与自助工作台

**读者**：企业的平台管理员——负责"公司买了什么、部署在哪、谁能用哪个应用"。
**入口**：企业工作台 `/dashboard`（Platform 提供）。

> 企业内部配置（组织目录、集成、凭证）在另一个地方，见 [03 企业控制台配置](./03-企业控制台配置.md)。

## 2.1 菜单结构

**工作台**
- 企业工作台 `/dashboard`
- 部署管理 `/dashboard/deployments`
- 订阅计划 `/dashboard/subscription-plans`
- 访问观测 `/dashboard/observability`

**应用与授权**
- 应用中心 `/dashboard/applications`
- 角色授权 `/dashboard/authorizations`
- 成员权限 `/dashboard/member-permissions`
- 岗位职责目录 `/dashboard/role-catalog`

**目录**
- 主体目录 `/dashboard/subjects`
- 成员资料 `/dashboard/users`

## 2.2 首次开通

新企业按**开通向导** `/dashboard/onboarding` 逐步填报。你负责的步骤：

| 步骤 | 填什么 |
| --- | --- |
| `profile` 企业资料 | 企业名称、行业、联系人 |
| `auth_mode` 认证方式 | 员工怎么登录：账号密码 / 企业微信 / 钉钉 / 企业统一登录 |
| `applications` 应用选择 | 本次要开通哪些应用 |
| `deployment` 部署配置 | 企业访问域名、数据服务地址 |
| `connectivity` 连通性检查 | 点一下，确认平台能连上你的环境 |

汇智云运营方并行负责：商务确认、License 激活、发布闸门。

**开通完成的标志**：开通阶段变为 `active`。三个条件同时满足才会通过：

- License 状态 active
- License 与部署的下发关系 active
- 部署连通性检查 passed

**连通性通过 ≠ 开通完成**。只做完连通性检查就以为可以让全员进来用，会踩坑。

## 2.3 企业工作台首页

`/dashboard` 汇总：当前开通阶段、应用启用进度、最近部署状态、关键告警。

每周扫一眼即可，出现红色告警时按 [14 常见问题](./14-常见问题.md) 处理或联系汇智云支持。

## 2.4 部署管理

`/dashboard/deployments` 维护企业访问域名、员工登录方式、数据服务地址与服务器安装。

**关键理解**：各应用**默认继承企业级数据服务地址**，只有特殊情况才在应用中心单独覆盖。不要一上来就给每个应用单独配地址，会让后续维护变复杂。

这一页能做的事：

- 配置企业访问域名（员工打开的地址）
- 设置员工登录方式
- 配置数据服务地址（tenant-runtime / data-runtime）
- 获取服务器安装指令
- 发起连通性检查并查看历史结果

**改动前先想清楚影响面**：改域名和登录方式会影响全员，改完要通知大家。

## 2.5 订阅计划

`/dashboard/subscription-plans` 选择或调整企业套餐。

- 新订阅提供 **30 天免费试用**，试用到期日会随订阅状态展示。
- 试用期后进入正式订阅期（1 年）。
- 续订在现有到期日基础上 +1 年，随时可续，提前续不损失时间。
- 加应用、换套餐在这里发起；减应用前先确认数据保留策略（停用不删数据，但员工会立即失去入口）。

**盯住到期日**。到期前一个月开始跟进续订，不要等到失效当天。

## 2.6 应用中心

`/dashboard/applications` 查看企业可用的业务应用。

**订阅计划包含的应用会自动开通，无需逐个启用。** 这里主要用于：

- 确认某个应用是否已开通
- 查看应用的运行状态与版本
- 特殊情况下为单个应用覆盖数据服务地址（默认继承企业级配置，非必要不覆盖）

看得到应用但员工进不去，问题在授权，不在这一页——去 [05 角色与权限管理](./05-角色与权限管理.md)。

## 2.7 访问观测

`/dashboard/observability` 统一查看各应用的前端性能、接口错误和慢请求摘要，并维护租户级采样策略。

用途：

- 员工反馈"系统很慢"时，看是全局慢还是某个页面慢
- 出现大量接口错误时，判断是否需要联系汇智云支持
- 调整采样策略，控制观测数据量

排查时带上：出问题的应用、时间窗口、具体页面路径。

## 2.8 主体目录与成员资料

- **主体目录** `/dashboard/subjects` — 企业的人员、部门与职位目录；也可以在这里为用户分配角色权限。
- **成员资料** `/dashboard/users` — 管理企业成员的账号、显示名与登录状态。

> 这两页是**平台侧视图**。日常的组织架构维护（建部门、调岗、目录同步）在企业控制台做，见 [04 组织目录管理](./04-组织目录管理.md)。两边看到的是同一份数据，改哪边都生效，但建议统一在企业控制台维护，避免混乱。

## 2.9 平台管理员的例行工作

| 频率 | 做什么 |
| --- | --- |
| 每周 | 看一眼工作台告警、访问观测有无异常 |
| 每月 | 复核成员权限，清理离职人员账号 |
| 每季度 | 用岗位职责目录检查过宽角色（见 [05](./05-角色与权限管理.md)） |
| 到期前 1 个月 | 跟进订阅续订 |
| 应用升级后 | 确认部署版本一致、连通性正常 |
