# 07 Codocs 文档

**做什么**：写文档、多人实时协同、知识沉淀、文档评审与归档。
**谁在用**：全员。

## 7.1 菜单结构

| 分组 | 页面 |
| --- | --- |
| **文档中心** | 首页 |
| **个人文档** | 我的文档、日志周报、协同文档、演示文稿、文件柜、收藏夹、回收站 |
| **项目文档** | 项目组文档、代码库文档 |
| **部门文档** | 协同文档、日志周报、会议记录、对外发文、部门规章、文件柜 |
| **组织资产** | 公司制度、通知公告、法务合规、企业文化、技术规范、产品资料、公司知识库、部门开放文档、文档模板 |
| **资讯中心** | 前沿资讯、推荐文章 |
| **审阅中心** | 审阅任务与归档 |
| **系统管理** | 管理资讯书签、归档文档、图片清理、用户管理、系统日志 |
| **使用指南** | Markdown 教程、Mermaid 语法 |

## 7.2 先搞清楚文档放哪

Codocs 按**归属**组织文档，写之前先决定放哪个空间——决定了谁能看到：

| 空间 | 谁能看 | 放什么 |
| --- | --- | --- |
| 个人文档 | 只有你（除非分享） | 草稿、个人笔记、日志周报 |
| 项目文档 | 项目成员 | 需求、设计、测试、交付物 |
| 部门文档 | 部门成员 | 部门规章、会议记录、周报 |
| 组织资产 | 全公司（按授权） | 公司制度、技术规范、知识库 |

**放错了怎么办**：可以移动，但历史链接和引用会受影响。写之前想 3 秒比事后搬省事。

## 7.3 日常操作

**新建文档**：在目标空间点新建。可以从**文档模板**（组织资产 → 文档模板）起步，公司标准化的 PRD、方案、会议纪要都在那里。

**多人协同**：多人同时编辑同一篇文档，改动实时同步，能看到别人的光标。不需要"锁定/解锁"，也不会互相覆盖。

**版本**：文档自动保留历史版本，可以查看和回退。重要节点建议手动标注版本说明。

**收藏与最近**：常用文档加收藏夹；最近打开的在"最近使用"里，不用记路径。

**回收站**：删除的文档进回收站，可以恢复。回收站清空后不可恢复。

**文件柜**：个人和部门都有文件柜，用于归档不再频繁修改但需要留存的材料。

**演示文稿**：支持直接写演示文稿，适合评审汇报，不用另开 PPT。

## 7.4 日志与周报

个人和部门都有"日志周报"入口：

- 个人写工作日志和工作周报
- 部门汇总部门日志周报
- Aims 项目里也有项目周报，与这里是不同层次：项目周报讲项目进展，个人周报讲个人工作

用日志周报的好处是内容沉淀在文档系统里，可搜索、可引用，不会散在聊天记录里。

## 7.5 审阅中心

需要正式发布的文档（公司制度、对外发文、技术规范）走审阅流程：

1. 作者在对应空间提交发布/审阅。
2. 审阅任务出现在审阅人的**审阅中心**和企业控制台的**我的待办**里。
3. 审阅人给意见：通过或退回。
4. 通过后文档发布到组织资产，进入正式生效状态。

**角色**：
- `codocs:publisher`（发布审阅）— 处理组织资产发布与审阅归档
- `codocs:records_manager`（档案管理员）— 治理企业档案、项目档案、部门档案和审阅归档

## 7.6 跨应用协同

Codocs 是全公司**文档正文的唯一事实源**，其他应用只引用文档标识，不复制内容：

| 应用 | 怎么用 Codocs |
| --- | --- |
| **Aims** | 项目文档嵌入 Codocs 编辑器；项目文档质量检查针对必交文档 |
| **Altoc** | 客户、商机、合同相关文档自动关联到 Codocs |
| **Assets** | 资产、产品、交付成果的说明文档引用 Codocs 文档 |
| **People** | 岗位说明、绩效说明、复盘报告引用 Codocs 文档 |

**含义**：在 Aims 项目里打开的文档，和在 Codocs 里打开的是同一篇。在哪改都一样。

## 7.7 角色一览

| 角色 | 能做什么 |
| --- | --- |
| `codocs:viewer` | 查看被授权的文档 |
| `codocs:editor` | 创建、编辑被授权范围内的文档 |
| `codocs:publisher` | 处理组织资产发布与审阅归档 |
| `codocs:records_manager` | 治理企业/项目/部门档案与审阅归档 |
| `codocs:space_admin` | 管理文档空间、项目文档、部门文档、组织资产、资讯空间 |
| `codocs:admin` | 管理应用配置、发文执行与全局文档能力 |

大部分员工给 `codocs:editor` 就够。

## 7.8 使用建议

1. **能放公共空间就别放个人空间。** 知识放在个人文档里等于没沉淀。
2. **用模板。** 公司已经沉淀了模板，从模板起步比从空白页起步质量高得多。
3. **标题写清楚。** 全公司搜索靠标题，"新建文档(3)" 这种谁都找不到。
4. **正式文档走审阅。** 制度、规范、对外材料别直接发，走审阅流程留痕。
5. **别在文档里贴密码密钥。** 那些属于企业控制台的凭证库。
