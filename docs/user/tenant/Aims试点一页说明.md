# Aims 试点一页说明

适用：日常事务、维保与交付项目的负责人、成员和审批人。详细操作见[用户手册](08-应用-Aims项目.md)。

1. **进入项目**：登录企业工作台，打开 Aims，从“我的项目”进入已分配项目。找不到项目时请负责人核对成员关系与权限；日常工作使用本人账号，无需切换角色。
2. **更新任务**：打开项目任务/工作项，确认负责人、截止时间和验收要求。开始工作更新进度，遇到阻断写明原因与下一动作；完成后补交付物链接。只登录或刷新不计有效参与。
3. **按类型执行**：日常事务（routine）直接使用事项与工时，不发起立项、不建里程碑；交付项目按项目模板推进立项与里程碑；维保按服务周期执行，关期前处理未结项和必要的例外说明。
4. **发起审批**：负责人在项目或里程碑对应入口提交，先补齐必填信息与必交文档。审批人用本人账号处理，驳回后按原因修改再提交；无审批权限时联系管理员核对授权，不借用他人账号。
5. **归档文档**：交付物放入项目文档并关联任务/里程碑，正文在 Codocs 中维护。验收前由 QA 检查清单，避免文档只留在个人空间或聊天中。
6. **报障**：记录发生时间、项目/任务编码、操作步骤、期望与实际结果、界面提示。发给已约定的维护负责人；不要发送密码、Token 或私人资料。页面超时后先查对象状态，避免重复创建。

试点约定：先选 1–2 个项目组，连续使用 5 个工作日；周会直接查看系统任务、里程碑与阻断。负责人每周五核对在管项目清单、应参与人员和实际有效操作，保留连续两周数据；不以集中补录代替持续使用。
