# 11 Assets 资产

**做什么**：企业资产与资源管理——实物设备、软件订阅、知识产权、数字资产、采购、环境交付。
**谁在用**：行政、IT、采购、资产保管人、部门/项目负责人，以及全员（领用归还）。

## 11.1 菜单结构

| 分组 | 页面 |
| --- | --- |
| **工作台** | 资产概览 |
| **资产台账** | 实物资产、产品资产、知识产权、数字资产、资源资产 |
| **资产视图** | 资产总览、环境视图、客户交付视图 |
| **采购管理** | 供应商、采购单、入库激活 |
| **资产操作** | 领用、归还、调拨、报废等操作 |
| **离职回收** | 离职员工未归还资产的回收协调 |
| **预警中心** | 到期、配额等预警 |
| **报表统计** | 资产报表 |
| **系统管理** | 资产类别管理、字典管理、跨应用操作 |

## 11.2 五类资产

| 类别 | 举例 |
| --- | --- |
| **实物资产** | 笔记本、服务器、显示器、办公设备 |
| **产品资产** | 公司的产品与版本主档 |
| **知识产权** | 专利、商标、著作权 |
| **数字资产** | 域名、证书、账号类数字资产 |
| **资源资产** | 云服务订阅、软件席位、SaaS 授权 |

分类边界不清时，应用内的**资产类别管理**和分类口径说明能帮你判断。**分类决定了后续的成本归因和报表口径**，建档时定对，改起来麻烦。

## 11.3 资产全生命周期

```
采购申请 → 审批 → 采购单 → 入库激活 → 资产台账
                                          ↓
                            领用 → 使用 → 归还 / 调拨 / 报废
                                          ↓
                                  离职回收（员工离职时）
```

**每个环节都走审批**（Workflow）。审批人由 `assets:asset_approver` 角色的人担任，与采购经办（`assets:procurement`）必须是不同的人。

### 采购

1. 提申请（`assets:requester` 或 `assets:owner`）。
2. 审批。
3. 采购经办建采购单、维护供应商。
4. 到货后做入库激活，资产进入台账。

### 领用与归还

普通员工（`assets:employee`）可以：
- 查看本人相关资产
- 发起领用、归还、释放等资产操作

在**资产操作**页发起，走审批后生效。

### 离职回收

员工离职时，未归还资产会形成回收协调任务。

这是 People 和 Assets 联动的：People 确认员工离职事实后，会把未归还资产的回收需求投影到 Assets，形成回收案例。行政或保管人跟进闭环。

## 11.4 三个视图

| 视图 | 回答什么问题 |
| --- | --- |
| **资产总览** | 公司一共有哪些资产、状态分布 |
| **环境视图** | 某个环境（开发/测试/生产）用了哪些资源 |
| **客户交付视图** | 交付给某个客户的资产有哪些、状态如何 |

**客户交付视图**与 Altoc 合同联动：合同履约启动时会同步客户交付资产计划，资产交付/上线/验收后状态会回写到 Altoc，推进履约义务和结算。

## 11.5 预警中心

监控需要提前处理的事：

- 订阅、证书、域名到期
- 席位/配额接近上限
- 资产保修到期
- 长期闲置资产

**建议每周看一次**。到期类预警放到最后一天处理往往来不及。

## 11.6 跨应用协同

| 方向 | 内容 |
| --- | --- |
| **Altoc → Assets** | 履约启动同步客户交付资产计划 |
| **Assets → Altoc** | 交付资产状态变更回写合同计划资产 |
| **Assets → Finance** | 项目资产成本摘要，进入项目核算 |
| **Aims ↔ Assets** | 项目环境、资产投入关联 |
| **People → Assets** | 离职员工未归还资产回收协调 |
| **Assets → Codocs** | 资产、产品、交付成果的说明文档（只引用文档标识） |

## 11.7 角色一览

| 角色 | 能做什么 |
| --- | --- |
| `assets:viewer` | 查看被授权范围内的资产、环境、交付、采购、预警和报表 |
| `assets:employee` | 查看本人相关资产，发起领用、归还、释放 |
| `assets:requester` | 查看资产目录，发起采购、领用、归还、释放申请 |
| `assets:custodian` | 维护本人或授权范围内的保管资产、资产操作和预警闭环 |
| `assets:owner` | 管理本部门或项目相关资产、采购申请、环境交付视图和预警闭环 |
| `assets:procurement` | 维护供应商、采购单和入库激活（**不含**资产审批和台账管理） |
| `assets:inventory_manager` | 维护资产台账、产品资产、环境交付视图、入库记录和资产操作（**不含**资产审批） |
| `assets:asset_approver` | 审批资产采购、领用、调拨、报废和关键资产变更 |
| `assets:finance` | 查看采购金额、成本归因、客户交付成本和资产报表 |
| `assets:admin` | 管理 Assets 全部资源、视图、采购、预警、报表和配置 |

**大部分员工给 `assets:employee` 就够。**

> 三个"不含"是刻意设计的职责分离：采购经办不能自己审批采购，台账管理员不能自己审批资产变更。别为了省事合并。

## 11.8 使用建议

1. **入库时把信息填全。** 序列号、保修期、采购单价，后面报表和预警全靠它们。
2. **资产归属要及时更新。** 人走了资产还挂在他名下，盘点时对不上。
3. **每周看预警中心。** 尤其证书和订阅到期。
4. **成本归因要落到项目或部门。** 不归的话项目毛利算不准。
5. **别用 Excel 平行维护一份台账。** 两份台账必然对不上，且没人知道哪份是对的。
