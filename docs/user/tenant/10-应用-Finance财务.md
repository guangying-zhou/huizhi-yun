# 10 Finance 财务

**做什么**：经营财务中台——发票、收款、核销、费用、付款、项目核算、财务报表。
**谁在用**：财务、会计、出纳、以及全员（费用报销）。
**状态**：🟡 开发中（MVP 阶段），部分功能可能与描述有出入。

> Finance 不做完整总账和税务申报。它是**经营财务**，聚焦合同回款、项目成本和费用管控。

## 10.1 菜单结构

| 分组 | 页面 |
| --- | --- |
| **财务工作台** | 财务概览 |
| **发票与收款** | 发票管理、开票申请、收款管理、核销管理 |
| **费用与付款** | 费用报销、项目支出、项目支出审批、付款申请 |
| **账户与资金** | 银行账户、余额快照、余额变动 |
| **项目核算** | 项目汇总、成本分摊、员工成本 |
| **个人绩效** | 绩效结果、贡献记录、绩效规则、计算快照 |
| **财务报表** | 经营财务报表 |
| **财务设置** | 财务科目、核算对象、科目映射、收入类型、费用类型、人力成本参数、审批实例、审计日志、跨应用操作 |

## 10.2 收入侧：开票 → 到账 → 核销

```
开票申请（来自 Altoc 回款计划，或在 Finance 直接发起）
    ↓ 审批（开票审批人）
正式发票
    ↓ 客户付款
到账 / 收款登记
    ↓ 核销
核销完成 → 回写 Altoc 合同财务摘要
```

**开票申请**大多来自 Altoc——销售在回款计划上点发起，申请自动流到 Finance 并触发审批。财务不用重新录。

**核销**把发票和到账对上。核销完成后，Altoc 的合同已收/未收金额会自动更新，销售那边能直接看到。

## 10.3 支出侧：报销 → 审批 → 付款

| 页面 | 谁用 |
| --- | --- |
| 费用报销 | 全员提交，费用审批人审批 |
| 项目支出 | 项目相关支出，归到 `project_code` |
| 项目支出审批 | 审批人处理 |
| 付款申请 | 应付会计制单，出纳确认付款 |

**制单与付款必须是两个人**：应付会计（`finance:ap_accountant`）维护台账不执行付款，出纳（`finance:cashier`）确认付款不维护申请。这是职责冲突控制，配权限时不要合并。

## 10.4 项目核算

| 页面 | 内容 |
| --- | --- |
| 项目汇总 | 按项目看收入、成本、毛利 |
| 成本分摊 | 共享成本如何分到项目 |
| 员工成本 | 人力成本归集 |

**成本来源是自动汇集的**：

- 人力成本 ← People 的月度成本快照（基于 Aims 工时）
- 资产成本 ← Assets 的项目资产成本摘要
- 直接支出 ← Finance 自己的项目支出

所以项目核算准不准，取决于工时填得准不准、资产归因对不对。

**人力成本参数**（财务设置 → 人力成本参数）由 Finance 维护：基本工资、福利费率、管理分摊系数、固定资源分摊。People 用这些参数生成月度成本快照。

## 10.5 个人绩效（财务口径）

Finance 负责绩效**金额**的财务口径快照——提成、奖金的计算与快照留存。

绩效周期、评分、确认这些人事流程在 People，不在 Finance。两边分工：**People 管过程，Finance 管钱**。

## 10.6 财务设置

| 设置项 | 什么时候配 |
| --- | --- |
| 财务科目 | 初始化时一次性配好 |
| 核算对象 | 初始化 |
| 科目映射 | 初始化，业务类型变化时补 |
| 收入类型 / 费用类型 | 初始化，新业务出现时补 |
| 人力成本参数 | 初始化，薪酬结构调整时更新 |
| 审批实例 | 查看审批流转，排查用 |
| 审计日志 | 排查"谁改了什么" |
| 跨应用操作 | 排查跨应用同步失败 |

设置项需要 `finance:admin` 角色。

## 10.7 跨应用协同

| 方向 | 内容 |
| --- | --- |
| **Altoc → Finance** | 开票申请、合同与回款计划来源 |
| **Finance → Altoc** | 核销后回写合同财务摘要 |
| **Aims → Finance** | 项目、里程碑、工时、验收事实 |
| **Assets → Finance** | 项目资产采购、资源订阅、环境投入成本摘要 |
| **People ↔ Finance** | Finance 提供成本参数，People 生成成本快照回流 |
| **Finance → Workflow** | 费用报销、项目支出、付款申请、开票申请审批 |

## 10.8 角色一览

| 角色 | 能做什么 |
| --- | --- |
| `finance:viewer` | 查看被授权范围内的发票、收款、支出、项目核算和报表 |
| `finance:expense_submitter` | 提交本人费用报销、项目支出和付款申请 |
| `finance:ar_accountant` | 维护开票、正式发票和收款台账（不审批、不确认收款） |
| `finance:ap_accountant` | 维护费用报销、项目支出和付款申请台账（不审批、不确认付款） |
| `finance:cashier` | 确认到账收款和费用付款（不维护申请审批、不管银行账户资料） |
| `finance:accountant` | 维护发票、收款、核销和支出台账（不审批、不确认） |
| `finance:reconciliation_operator` | 处理发票、收款、合同和回款计划核销确认 |
| `finance:invoice_approver` | 审批开票申请 |
| `finance:expense_approver` | 审批费用报销、项目支出和付款申请 |
| `finance:manager` | 管理财务台账、核销、项目核算、绩效和报表（默认不执行审批或付款确认） |
| `finance:report_viewer` | 查看和导出财务报表 |
| `finance:admin` | 管理 Finance 全部配置、权限和集成参数 |

**普通员工只需要 `finance:expense_submitter`**，能提报销就够了。

> 注意 `finance:manager`（财务负责人）**默认不含**审批和付款确认。要审批要单独给 `finance:invoice_approver` / `finance:expense_approver`。这是有意设计的。

## 10.9 使用建议

1. **开票申请从 Altoc 发起。** 从回款计划走，合同和金额自动带过来，少一道录入和一道对错的机会。
2. **及时核销。** 核销不做，销售那边看到的合同回款状态就是错的。
3. **项目支出一定要归项目。** 不归项目的支出进不了项目核算，毛利就算不准。
4. **职责分离不要嫌麻烦。** 制单与付款、开票与收款分开，是防错也是防风险。
5. **别把 Finance 当总账用。** 它是经营财务，总账和税务申报仍走专业财务软件。
