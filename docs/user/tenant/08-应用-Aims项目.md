# 08 Aims 项目

**做什么**：研发项目从立项到交付的全生命周期管理。
**谁在用**：项目经理、产品经理、开发、测试、PMO、项目总监。

## 8.1 PIVR 四阶段

Aims 里所有项目统一走 **PIVR** 四阶段：

| 阶段 | 全称 | 干什么 |
| --- | --- | --- |
| **P** | Planning 规划 | 立项、需求梳理、里程碑与计划 |
| **I** | Implementation 实施 | 迭代开发、任务执行、工时记录 |
| **V** | Verification 验收 | 测试、质量检查、验收确认 |
| **R** | Release 交付 | 发布、交付物归档、项目收尾 |

里程碑与合同回款节点是映射的——项目做到哪一步，经营侧的回款计划就推进到哪一步。应用内 **使用指南 → PIVR** 有完整说明。

## 8.3 常见操作

### 立项

1. 项目总览 → 新建项目。
2. 可以从**项目模板**创建，模板带好了里程碑结构和必交文档清单。
3. 填基本信息、关联客户/合同（如果来自 Altoc 商机）、指定项目经理。
4. 提交立项审批（需要 `aims:project_approver` 角色的人审批）。

**从合同自动建项目**：Altoc 合同生效时可以直接编排出交付项目，不用手工建。经营和交付两侧的关联是自动的。

### 规划里程碑

在项目 → 里程碑里按 PIVR 排计划。如果项目关联了合同，付款条款会同步成里程碑，做完对应里程碑就能推进回款。

### 管理工作项与任务

工作项分层：Epic → Story → Task → Sub-task。

- **目标**页管工作项（要做什么）
- **任务**页是看板（谁在做、做到哪了）
- 工作项支持追加、拆解、分解

**个人视角**用左侧的"我负责的 / 我参与的 / 我创建的 / 待我验证"四个过滤入口，比每天翻项目快。

### 填工时

在项目 → 工时里填报。项目经理审核。

工时数据会流向：项目成本核算（Finance）、人员投入分析（People）、项目资源视图。**认真填，它不只是走个形式。**

### 质量检查

必交文档由 QA（`aims:qa`）按检查清单做完整性与质量检查。

- 项目模板里定义了哪些是必交文档
- 检查针对**确定版本**，不是随时抓一版
- 检查不通过要补齐才能推进验收

### 周报

项目周报在项目里写，跨项目汇总在"统计分析 → 周报汇总"。项目总监（`aims:project_director`）可以独立审阅并发布公司汇总。

## 8.4 跨应用协同

| 方向 | 内容 |
| --- | --- |
| **Altoc → Aims** | 合同生效自动创建交付项目，付款条款同步为里程碑 |
| **Aims → Altoc** | 验收里程碑完成后推进回款计划到"可开票" |
| **Aims ↔ Codocs** | 项目文档内嵌 Codocs 编辑器，文档正文存在 Codocs |
| **Aims → Finance** | 项目工时与成本进入项目财务核算 |
| **Aims → People** | 项目贡献进入个人绩效快照 |
| **Aims ↔ Assets** | 项目环境、资产投入关联 |
| **Aims → Insights** | 项目关联的代码仓库贡献分析 |

**"跨应用操作"页**（系统管理下）用于查看这些跨应用动作的执行状态。出现失败时先看这里，能看到具体是哪一步、什么原因。

## 8.5 角色一览

| 角色 | 能做什么 |
| --- | --- |
| `aims:viewer` | 查看分配给自己的项目与工作项 |
| `aims:member` | 执行项目任务、提交工时、参与看板流转 |
| `aims:pm` | 管理项目计划、迭代、人员、工时审核和工作项确认 |
| `aims:pmo` | 管理项目组合、跨项目交付质量、工时审核和研发报表（不含项目审批） |
| `aims:project_director` | 审阅项目周报、发布公司汇总、处理 QA 豁免和里程碑完成审批 |
| `aims:qa` | 维护文档检查清单并检查必交文档 |
| `aims:project_approver` | 处理立项、项目变更、验收和重大里程碑审批 |
| `aims:admin` | 管理全局配置与项目模板 |

> 注意 `aims:pm` 的管理范围主要由**项目关系或授权范围**决定，不是全局的。给项目经理配权限时要配上他负责的项目范围。
>
> `aims:pmo` **不包含**项目审批。审批要单独给 `aims:project_approver`。

## 8.6 使用建议

1. **用项目模板起步。** 模板带好了里程碑和必交文档，比每次从零搭省事且更规范。
2. **里程碑要和合同对齐。** 对不齐的话回款推进会卡住。
3. **工时按天填。** 攒到月底补，数据没有参考价值。
4. **文档写在项目文档里。** 别散在个人空间或 IM 里，交付时找不到。
5. **验收前先过质量检查。** 必交文档不齐，验收会被打回。
