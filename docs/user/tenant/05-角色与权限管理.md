# 05 角色与权限管理

**入口**：企业工作台 `/dashboard` → 应用与授权
**读者**：负责给同事配权限的人

这是整套系统里最需要想清楚的一章。配错了要么同事干不了活，要么该管住的没管住。

## 5.1 先理解四个层次

```
应用角色        「aims:pm 能管项目计划、迭代、人员、工时审核」   ← 定义"能做什么"
    ↓
企业角色        「项目经理 = aims:pm + codocs:editor」          ← 组合应用角色
    ↓
授权给谁        「张三、李四是项目经理」                        ← 分配主体
    ↓
对象范围        「张三只管 P-2026-001 这个项目」                ← 定义"能对哪些对象做"
```

**只配角色不配范围 = 他能对全公司数据做这件事。** 两者缺一不可。

### 企业全量资格不会自动授权员工

企业全量功能资格表示企业在有效期内可以使用全量功能；它不会创建员工角色、扩大既有角色的动作，也不会扩大部门、项目或其他对象范围。员工打不开应用时，先看入口显示的状态：模块未配置、未部署、服务不可用和人员缺权是不同问题，处理表见[企业开通与自助工作台](./02-企业开通与自助工作台.md#企业资格模块状态和人员权限)。

因此不要为了让某人进入模块而把企业资格、旧套餐或“管理员”角色当作万能开关。应在“成员权限”中确认该员工的有效角色、敏感动作和对象范围，再按最小必要原则补齐。

## 5.2 三个页面各管什么

| 页面 | 做什么 |
| --- | --- |
| **角色授权** `/dashboard/authorizations` | 选择企业角色，按角色集中为成员分配授权 |
| **成员权限** `/dashboard/member-permissions` | 按成员查看有效角色、权限来源和对象范围 |
| **岗位职责目录** `/dashboard/role-catalog` | 按职责类型给角色分组，辅助清理过宽角色 |

**配权限用「角色授权」（从角色出发），查权限用「成员权限」（从人出发）。**

## 5.3 角色授权

`/dashboard/authorizations` — 在当前企业下选择平台预置的企业角色，并按角色集中为成员分配授权。

**操作流程：**

1. 从角色列表里点选一个企业角色。
2. 卡片上可以查看该角色包含哪些权限（"查看权限"）、已授权给哪些人。
3. 点"分配"打开授权弹窗。
4. 在主体树里勾选人员/部门/委员会——支持关键词搜索。
5. 可以设置**有效期**（到期自动失效），适合临时授权、代理岗位。
6. 保存。

**撤销授权**在同一个弹窗的已授权列表里操作。

### 角色状态要留意

角色卡片会显示策略状态：

| 状态 | 含义 | 要做什么 |
| --- | --- | --- |
| 已同步 | 角色定义与平台一致 | 无需处理 |
| 系统已更新 | 平台侧角色定义更新了 | 点"同步"应用新定义 |
| 企业已覆盖 | 你们自定义过这个角色 | 正常，注意平台更新不会自动合并 |
| 已漂移 | 与平台定义不一致 | 点"查看差异"确认，再决定同步还是保留 |

### 自定义企业角色

平台预置角色不够用时可以自建。规则：

- **不要把部门、项目、客户名编进角色名**。"华东区销售经理"是错的——地域由对象范围表达，角色只叫"销售经理"。
- 自建角色只要状态是启用、可分配，就会正常生效，不会因为"不是平台预置的"而被限制。
- 组合应用角色时按最小必要原则，别图省事全勾上。

## 5.4 成员权限

`/dashboard/member-permissions` — 按成员查看有效角色、权限来源和对象范围，并在当前页进行内联模拟解释。

**这是排查权限问题的第一站。** 输入某个员工，能看到：

- 他实际拥有哪些角色
- 每个权限是从哪来的（哪个企业角色、哪次授权）
- 每个权限的对象范围是什么
- 授权的有效期

**重要概念：权限是合并的。** 一个人有多个角色时，系统会合并他的**全部有效授权**，不需要"切换角色"才能拿到日常权限。如果同事反馈"我要切成管理员才能操作"，那是配置或理解有误，不是正常行为。

## 5.5 两个诊断工具

角色授权页内置两个排查工具，遇到问题先用它们，比猜快得多。

### 检查员工是否有某项权限

回答"为什么能/不能打开或操作某个对象"。

输入员工 + 资源 + 动作 + 具体对象，它会告诉你：
- 结论（有权 / 无权）和原因代码
- 如果有权，是哪条授权命中的：角色编码、授权来源类型、主体类型、对象范围

**同事说 403 时，先跑这个。** 它直接告诉你缺的是角色还是范围。

### 检查单据是否会触发职责冲突

回答"为什么不能审批/确认这张单据"。

输入具体单据，返回命中了哪几条职责冲突规则及其状态。

## 5.6 职责冲突规则

角色授权页有**职责冲突规则**面板，显示已启用几条 / 共几条。

职责冲突用来防止同一个人既当运动员又当裁判员，典型场景：

| 场景 | 要拆开的两件事 |
| --- | --- |
| 自审批 | 提交人 ≠ 审批人 |
| 采购 | 采购经办 ≠ 采购审批 |
| 付款 | 制单 ≠ 付款确认 |
| 开票收款 | 应收会计 ≠ 出纳 |
| 生产发布 | 开发 ≠ 发布审批 |

汇智云的应用角色已经按这个思路拆好了——比如 `assets:procurement`（采购经办）和 `assets:asset_approver`（资产审批人）是两个角色，`finance:ar_accountant`（应收会计）和 `finance:cashier`（出纳）是两个角色。**配权限时不要把它们给同一个人**，规则会拦。

小公司人手紧张确实可能一人身兼两职。这种情况要么调整规则的执行强度，要么在流程上加补偿控制（比如事后复核），但要有意识地做决定，别默默绕过去。

## 5.7 岗位职责目录

`/dashboard/role-catalog` — 将企业角色按主岗位、管理职责、审批职责和高风险特权分组，辅助清理过宽角色。

四类分组：

| 分组 | 含义 |
| --- | --- |
| 主岗位 | 日常本职工作需要的角色 |
| 管理职责 | 管人管事的角色 |
| 审批职责 | 有审批权的角色 |
| 高风险特权 | 影响面大、需要重点管控的角色 |

**建议每季度用这一页做一次盘点**：看看有没有人在"高风险特权"分组里但实际不需要，以及有没有角色包含的权限远超过它的岗位描述。

## 5.8 权限设计的六条经验

1. **按岗位配，不要按人配。** 一人一套定制权限，人一走就没人看得懂。
2. **角色 + 范围一起给。** 只给角色不给范围等于放开全公司。
3. **敏感动作单独授权。** `admin` 只默认包含同资源的查看/编辑/管理；审批、确认、导出、关闭、发布这些必须单独给。别指望"给个管理员就都能做"。
4. **临时授权用有效期。** 代理、支援、临时项目都设到期日，比事后清理靠谱。
5. **优先用动态关系授权。** 审批任务的处理人、项目成员、商机负责人、文档分享对象、资产使用人这类，系统会按对象关系自动判定，不要为此新建一堆全局静态角色。
6. **别用前端隐藏当安全边界。** 菜单看不见不代表接口调不通。真正的控制在服务端，所以范围一定要配对。

## 5.9 排查流程

同事说"我打不开 / 操作不了"：

1. **成员权限**页查他现有角色和范围。
2. **检查员工是否有某项权限**，输入具体资源+动作+对象，看原因。
3. 按结果处理：
   - 缺角色 → 角色授权页分配
   - 缺范围 → 分配时补上对象范围
   - 敏感动作未授权 → 单独授予该动作
   - 命中职责冲突 → 见 5.6，考虑换人或调整流程
   - 授权已过期 → 重新授权
4. 改完让他**重新登录**，权限刷新需要新会话。
5. 还不行 → 联系汇智云支持，带上：员工标识、资源、动作、对象、诊断结果截图。

## 5.10 定期复核清单

| 频率 | 检查 |
| --- | --- |
| 每月 | 离职人员的授权是否已全部撤销 |
| 每月 | 转岗人员的原岗位权限是否已回收 |
| 每季度 | 用岗位职责目录检查"高风险特权"分组 |
| 每季度 | 检查有效期已过的授权是否需要续期或清理 |
| 每季度 | 检查是否有角色出现"已漂移"状态 |
| 每年 | 全量复核一次企业角色定义是否还匹配实际组织 |
