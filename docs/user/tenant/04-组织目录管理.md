# 04 组织目录管理

**入口**：企业控制台 → 目录管理
**需要的角色**：`console:directory_manager`（完整管理）或 `console:directory_operator`（基础数据维护）

组织目录是全公司的唯一事实源。部门、人员、项目在这里维护一次，所有业务应用共用。**不要在各个应用里重复建人员和部门。**

## 4.1 五个页面

| 页面 | 路径 | 管什么 |
| --- | --- | --- |
| 部门 | `/directory/departments` | 组织架构树 |
| 委员会 | `/directory/committees` | 跨部门的固定组织 |
| 用户 | `/directory/users` | 员工账号与目录信息 |
| 代码仓库 | `/directory/projects` | 项目注册表 |
| 目录源配置 | `/directory/sources` | 从哪里同步组织数据 |
| 目录同步 | `/directory/sync` | 执行与追踪同步 |

## 4.2 跨应用标识

这几个标识会出现在所有应用里，**一旦分配就不要改**：

| 标识 | 代表 | 说明 |
| --- | --- | --- |
| `uid` | 用户 | 员工的唯一标识 |
| `dept_code` | 部门 | 部门的唯一编码 |
| `project_code` | 项目 | 项目的唯一编码 |

改这些编码会导致历史数据关联断裂（文档归属、项目成员、资产使用人、审批记录全部受影响）。人员转岗改部门归属可以，改 `dept_code` 本身不行。

## 4.3 部门

`/directory/departments` 维护组织架构树。

**建议做法：**

- 部门编码用有意义的短码（如 `RD`、`SALES`、`RD-FE`），不要用纯数字流水号。
- 层级不要超过 4 层。层级深了权限的数据范围会很难配。
- 每个部门指定负责人——很多应用的默认审批人、数据范围继承都依赖它。
- 撤销部门时先把人员转出，再停用部门，不要直接删。

**部门与权限的关系**：数据范围可以按部门授予（"这个人能看研发部的数据"），并且支持沿组织树继承。所以组织树的形状直接决定权限配置的复杂度。

## 4.4 委员会

`/directory/committees` 维护跨部门的固定组织，如技术委员会、评审委员会、安全小组。

成员角色分四类：

| 角色 | 是否授权主体 |
| --- | --- |
| 主任 | 是 |
| 秘书 | 是 |
| 委员 | 是 |
| 观察员 | **否**，仅用于名册展示 |

也就是说：给委员会授权时，只有主任、秘书、委员会真正拿到权限，观察员不会。想让某人有权限就不要把他放在观察员里。

## 4.5 用户

`/directory/users` 维护员工的账号与目录信息：姓名、工号、邮箱、部门、职位、状态。

**入职**：未启用 HR 事实源时可在 Console 建立目录用户；启用 People/钉钉 HR 事实源后，应在事实源中办理入职，系统自动投影账号与正式部门归属，再分配角色（见 [05](./05-角色与权限管理.md)）。

**转岗**：启用 People/钉钉 HR 事实源后，在事实源修改人员主归属，不要在 Console 普通编辑页覆盖。原部门的数据范围授权会随之失效——如果他还需要看原部门数据，要单独授权。

**离职**：启用 People/钉钉 HR 事实源后，在事实源确认离职和最后工作日；到期后 Console 会先自动停用系统访问。紧急情况仍可由有权限的 Console 管理员立即停用账号。

> 离职处理要点：停用目录账号只是切断登录。资产回收、文档交接、审批任务转交要分别处理。如果启用了 People 模块，走 People 的离职交接流程会更完整（见 [12](./12-应用-People人员.md)）。

**用户信息从哪来**：LDAP / 企业微信是技术目录源；钉钉配置为 HR 事实源时，正式行政部门、人员主归属和在离职状态由 People 管理的钉钉同步接管。委员会、虚拟组织、项目组和稳定 `dept_code` 仍由汇智云维护。

**钉钉部门停用保护**：同步只会把通过完整性校验后消失的正式部门列为差异，不会直接停用。People 管理员需要在「设置 / 人事事实源」逐项确认；仍有活跃主归属人员或未同时处理的子部门时，系统会拒绝停用。超过安全阈值或根部门变化会显示高风险提示，应先检查钉钉应用的通讯录可见范围。

## 4.6 代码仓库（项目注册表）

`/directory/projects` 维护项目注册表，是 Aims、Codocs、Assets、Insights 共用的项目基准。

每个项目有 `project_code`，以及项目成员名册。Aims 的项目、Codocs 的项目文档、Assets 的项目资产归因都引用它。

## 4.7 目录源配置

`/directory/sources` 配置组织数据从哪里同步。支持三种源：

| 源 | 说明 |
| --- | --- |
| **LDAP** | 企业 LDAP / AD 目录源 |
| **企业微信** | 企业微信通讯录同步 |
| **钉钉** | 在 Console 保存连接与凭证；HR 组织同步由 People「设置 / 人事事实源」操作 |

**凭证处理**：敏感凭证可由凭证库（Vault）加密保存，也可以使用外部 secret 引用。不要把密码明文填在配置里。

**LDAP 配置验证**：保存配置后会触发一次检查，由客户侧 Directory Connector 完成网络/TLS、Bind 凭据和 User Base 读取三项验证。

- 三项都通过 → 配置可用
- 60 秒内没收到结果 → 确认 `hzy-data-runtime-directory` 服务是否在线
- 某项失败 → 页面会给出具体失败原因，按提示修正

## 4.8 目录同步

`/directory/sync` 执行并追踪同步任务。

**两类同步：**

1. **Console Directory → Platform 主体投影** — 从组织目录生成最小 subject 投影同步到平台，供角色授权时选择主体用。正常入转调离由 lifecycle operation 自动推进；仅在任务进入失败/死信状态时由管理员按任务审计信息重试。

2. **外部技术目录同步（LDAP 等）** — 由客户侧 Connector 执行。钉钉 HR 同步不在此页启动，由具有 `people:admin` 的管理员在 People 操作。

所有同步动作都有记录，可以按任务查看详情 `/directory/sync/{jobCode}`，便于审计和重试。

**同步失败的常见原因**：
- 外部系统凭证过期 → 到凭证库更新
- Connector 服务离线 → 检查企业连接运行时
- 网络策略变更 → 检查防火墙与出站规则
- 源数据不合规（缺必填字段、编码冲突）→ 看任务详情的错误明细

## 4.9 日常维护建议

| 频率 | 动作 |
| --- | --- |
| 有入职/离职/转岗时 | 当天在 People/HR 事实源处理并检查 lifecycle 状态；仅失败或死信时按审计信息重试 |
| 每月 | 核对目录用户数与实际在职人数 |
| 每季度 | 检查部门树是否还反映真实组织，清理空部门 |
| 每季度 | 核对委员会名册 |
| 外部系统改造后 | 验证目录同步是否仍正常 |
