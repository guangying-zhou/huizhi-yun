# 08 部署与运行诊断

页面：`/admin/deployments`（运行诊断）

## 8.1 这一页的定位

运行诊断是**开通编排之后的诊断支撑页**，重点查看四样东西的运行状态：

| 对象 | 回答的问题 |
| --- | --- |
| **deployment** | 客户的运行环境配置对不对、能不能连上 |
| **heartbeat** | 客户实际跑的是哪个版本、还活着吗 |
| **bundle** | 策略包（授权规则）下发到哪一版了 |
| **license** | 授权凭据是否有效、绑到哪些部署 |

客户报障时，从这四项开始查。

## 8.2 部署配置

一个 deployment 描述租户的一个运行环境：部署编码、部署名称、部署模式、企业端 URL、runtime 地址、basePath、API 前缀、状态。

同一租户可以有多个 deployment（生产/测试、多地域）。**deploymentCode 一般由系统自动建议，只有多环境时才需要手工调整。**

## 8.3 连通性检查

从运行诊断页或客户的企业工作台都可以发起连通性检查，结果写入检查历史。

连通性状态：

| 状态 | 含义 | 处理 |
| --- | --- | --- |
| `passed` | 通过 | 无需处理 |
| `failed` | 失败 | 见 8.6 排查顺序 |
| 未检查 | 从未发起过 | 开通闸门无法通过，先发起一次 |

**注意**：连通性通过只代表"网络与基础握手正常"，不代表开通完成。开通闸门还要求 License active 且已下发。

## 8.4 心跳与版本

应用 runtime 启动后持续上报心跳，携带四个版本字段：

- `app_version` — 应用版本
- `manifest_version` — Manifest 版本
- `manifest_hash` — Manifest 内容哈希
- `sdk_version` — Foundation SDK 版本

心跳中断超过阈值会在工作台和部署列表出现异常标识。版本与登记 Release 不一致会出现**版本漂移告警**（处理方式见 [04](./04-Runtime发布管理.md#44-版本漂移怎么处理)）。

## 8.5 策略包与吊销

**策略包（Policy Bundle）**是平台签名下发给租户的授权规则集。租户角色、应用订阅、Manifest 变更都会触发新版本。诊断页显示当前部署拿到的是哪一版——客户说"权限改了没生效"，先看这里。

**吊销链路**用于强制下线：

```
产生吊销条目（登出 / 管理员强制下线）
        ↓
按租户聚合生成吊销快照
        ↓
记录快照分发目标
        ↓
runtime 拉取快照并校验签名后执行
```

排查"某个用户还能登录"时，按 `条目 → 快照 → 目标部署` 逐层追，看断在哪一层。

## 8.6 排查顺序（客户说"打不开"）

按这个顺序走，不要跳步：

1. **是全员还是个别人？**
   - 个别人 → 权限/账号问题，跳到第 5 步。
   - 全员 → 继续。

2. **看部署状态**：`/admin/deployments` 找到该租户的 deployment，看连通性与心跳。
   - 心跳中断 → 客户侧服务未运行或网络不通，联系客户/运维。
   - 连通性 failed → 看最近检查的失败摘要。

3. **看 License**：状态是否 active？是否绑定到这个 deployment？是否已过期？

4. **看策略包版本**：是否卡在旧版本？必要时触发重新下发。

5. **看具体用户的授权**：请客户管理员在企业工作台确认该用户被授予了对应应用角色和数据范围。

6. **看审计日志** `/admin/audit`：最近是否有人做过订阅、角色、部署相关的变更。

## 8.7 常见错误信号对照

| 现象 | 最可能的原因 |
| --- | --- |
| 页面 403，其他人正常 | 用户缺少应用角色或数据范围 |
| 页面 403，全员都是 | License 未激活或策略包未下发 |
| 提示 `insufficient_scope` | 跨应用服务授权（Console grant）缺失或漂移 |
| 提示 401 | 认证失败，检查 Token 与认证配置 |
| 提示 503 | 上游授权服务暂时不可用，可重试；持续出现要查 Console 侧 |
| 部分功能可用、部分 403 | 敏感动作（approve/export 等）未显式授权 |

> 出现 `insufficient_scope` 或授权失效时，正确做法是**修复授权漂移**，不是删掉精确 scope 或改用宽 scope 绕过。绕过会留下安全隐患且掩盖真实问题。

## 8.8 新建诊断对象

诊断页支持新建诊断对象，用于在没有正式部署前先验证一条链路是否可达。这是排查工具，不要用它代替正式的部署配置。
