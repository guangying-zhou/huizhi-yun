# 02 登录与运营工作台

## 2.1 登录

运营控制台登录地址：`/admin/login`。

- 使用平台账号（`platform_accounts`）登录，与企业侧的员工账号完全独立。
- 新运营同事由超级管理员在 `/admin/accounts` 建号，通过激活邮件（`/activate-email`）设置密码后生效。
- 登录后按你的平台角色显示菜单；看不到某个菜单说明角色没授权，不是功能缺失。

> 平台账号与租户账号是两套体系。同一个人若既是运营又要看客户环境，需要分别持有两边身份，不要共用。

## 2.2 菜单结构

运营控制台左侧分三组：

**工作台**
- 工作台 `/admin`

**产品**
- 应用 `/admin/applications`
- Runtime 发布 `/admin/runtime-releases`
- 订阅计划 `/admin/plans`
- 企业角色 `/admin/enterprise-roles`
- 应用权限角色 `/admin/system-roles`

**运营**
- 租户 `/admin/tenants`
- 开通编排 `/admin/subscriptions`
- 订单管理 `/admin/orders`
- 运行诊断 `/admin/deployments`

另有直达页面（通常从工作台或详情页跳转）：License `/admin/licenses`、发票 `/admin/invoices`、支付 `/admin/payments`、工单 `/admin/tickets`、公告 `/admin/announcements`、灰度开关 `/admin/feature-flags`、审计 `/admin/audit`、平台角色 `/admin/platform-roles`、运营账号 `/admin/accounts`、开通向导 `/admin/onboarding`。

## 2.3 工作台每天看什么

`/admin` 工作台是运营的起点，聚合两类信息：

**今日待办**
- 待审核的 Manifest 注册请求
- 待开通的租户
- 连通性检查失败的部署
- 待激活的 License
- 版本漂移的部署

**运行态概览**
- 活跃租户数、活跃部署数
- 心跳健康度
- 版本兼容状态

## 2.4 建议的每日动线

1. 打开 `/admin`，先清"今日待办"里的**红色项**（连通性失败、版本漂移）——这些是客户已经受影响的问题。
2. 处理待审核 Manifest（见 [03](./03-应用接入与Manifest治理.md)）——挡住它会挡住整条发布链。
3. 处理待开通租户与待激活 License（见 [06](./06-租户管理与开通编排.md)）。
4. 扫一眼工单 `/admin/tickets`，按客户影响面排序。

## 2.5 界面通用约定

- **状态用语义色**：绿色=正常/已生效，黄色=待处理/警告，红色=失败/已吊销，灰色=未启用/草稿。
- **列表都支持服务端搜索与分页**，改筛选条件会回到第 1 页；不要用"拉大页数"的方式导出，导出走列表页自带的导出动作（需要 `export` 权限）。
- **删除、停服、吊销等危险操作会弹确认框**，确认文案里会写明对象名和后果，看清楚再点。
- **技术 ID 默认折叠**，需要时展开复制；给客户沟通时用名称，排查时用 ID。
