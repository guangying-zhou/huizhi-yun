# 07 订单与计费

页面：订单 `/admin/orders`、发票 `/admin/invoices`、支付 `/admin/payments`、License `/admin/licenses`

## 7.1 一张图看清链路

```
客户下单  →  订单 Order  →  支付/到账确认  →  订阅激活（30天试用 + 1年）
                              │
                              ├→ 发票 Invoice
                              └→ License 签发与下发 → 部署可用
```

## 7.2 订单管理

`/admin/orders` 查看租户订阅订单。

**对公转账订单确认到账后，租户主订阅会按到账日期激活并进入 30 天试用期。**

处理对公转账订单：

1. 财务确认银行到账，拿到实际到账日期。
2. 在订单详情里确认到账——注意确认弹窗会提示"订单将从到账日期开始计算 30 天试用期"，核对日期无误再确认。
3. 确认后订阅自动激活，不需要再去别处点"开通"。
4. 确认动作有防重复保护，误点第二次不会重复延期。

**订单状态异常时**：不要用新建订单的方式"绕过去"，会造成订阅期限重复计算。先查订单详情的状态流转记录，找到卡在哪一步。

## 7.3 发票

`/admin/invoices` 查看平台订阅订单生成的发票、金额和支付状态。

发票由订单生成，不要脱离订单单独开票——否则发票与订阅事实对不上，对账时说不清。

## 7.4 支付

`/admin/payments` 查看平台订阅收款记录、支付渠道和人工确认信息。

人工确认的收款要在备注里写清楚：确认人、确认依据（银行流水号等）、到账日期。审计追溯时靠这些字段。

## 7.5 License

`/admin/licenses` 管理 License 台账。License 是订阅在技术侧的凭据，包含：

- 授权的应用与 capability 集合
- 有效期
- 下发到哪些部署（License 与部署的绑定关系）

**License 状态与订阅状态是两件事**：订阅是商业事实，License 是技术下发。订阅续了但 License 没重签，客户还是会到期失效。续订后确认 License 的到期时间也一并更新。

**capability 变更后**要重新下发到部署，否则客户侧策略包还是旧的。

## 7.6 续订

- 随时可续订，不必等临期。
- 续订在**现有到期日**基础上 +1 年，不是从续订当天算起。提前续订不会损失时间。
- 续订完成后检查：订阅到期日、License 到期日、License 下发状态三处一致。

## 7.7 停服

停服由运营手动执行，系统不自动停服。执行前：

- [ ] 商务口径已确认（欠费？主动退订？合同到期不续？）
- [ ] 已提前通知客户，并给出数据导出窗口
- [ ] 在租户详情页记录停服原因与决策人
- [ ] 明确是"停用订阅"还是"删除数据"——停用不删数据，客户业务数据仍在其租户库

## 7.8 对账要点

每个计费周期结束后核对三张表：

| 核对项 | 页面 | 应该一致 |
| --- | --- | --- |
| 订单金额 vs 发票金额 | `/admin/orders`、`/admin/invoices` | 金额、币种、租户 |
| 发票 vs 收款 | `/admin/invoices`、`/admin/payments` | 已付金额、支付渠道 |
| 订阅有效期 vs License 有效期 | `/admin/subscriptions`、`/admin/licenses` | 到期日 |

第三项最容易出问题，也最容易被客户在到期当天发现。
