# 06 租户管理与开通编排

页面：租户 `/admin/tenants`、开通编排 `/admin/subscriptions`、开通向导 `/admin/onboarding`

## 6.1 租户台账

`/admin/tenants` 是平台所有企业租户的总表，从这里查看订阅状态、部署健康，并下钻到单租户运营详情 `/admin/tenants/{code}`。

新建租户需要：租户编码（如 `C000001`）、企业名称、联系人信息、初始管理员邮箱。

**租户编码一旦创建不可更改**，它会出现在部署配置、License、审计日志和跨应用调用上下文里。命名前想清楚。

租户详情页汇总：组织信息、订阅、License、部署、最近审计事件、生命周期事件。客户来问任何问题，这一页是第一站。

## 6.2 开通阶段

租户有一个开通阶段（`onboarding_stage`），由**双轨**推进：

```
租户侧填报                     平台侧确认
─────────────                 ─────────────
profile      企业资料          commercial_review   商务确认
auth_mode    认证方式          license_activation  License 激活
applications 应用选择          release_gate        发布闸门
deployment   部署配置
connectivity 连通性检查
                    │
                    ▼
            release_gate 通过 → active
```

两轨可以并行，但最后统一由 `release_gate` 收敛。发布闸门的最小判定条件：

- License 状态为 `active`
- License 与部署的下发关系为 `active`
- 部署的连通性检查结果为 `passed`

> **连通性通过不等于开通完成。** 客户能打开页面但没通过闸门时，功能会受限，不要凭"我打开看了没问题"就告诉客户已开通。

## 6.3 开通编排（日常主力页面）

`/admin/subscriptions` 是开通的核心操作台。左侧选应用，右侧显示这次开通的**五个步骤**、阻塞点和必要配置：

| # | 步骤 | 做什么 | 完成标志 |
| --- | --- | --- | --- |
| 1 | 选择应用 | 从左侧选本次要开通的应用 | 应用已进入编排 |
| 2 | 建立订阅关系 | 保存一次编排，建立租户与应用关系 | 订阅阶段不再是"未订阅" |
| 3 | 配置 deployment | 补齐部署方式、部署名称、运行状态 | 已有 deploymentCode |
| 4 | 签发 license | 选择套餐后签发 License 与 capability | 已有 licenseCode |
| 5 | 通过 release gate | 授权、部署与连通性共同通过 | 应用正式启用 |

页面右上角有**推荐下一步**提示，卡住时按它走即可。

配置 deployment 时的几个字段：

| 字段 | 填法 |
| --- | --- |
| deploymentCode | 自动建议；只有多环境时才手工调整 |
| deploymentName | 例如 `AIMS · C000001` |
| basePath | 例如 `/aims/`；根应用用 `/` |
| API 前缀 | 默认 `/api/v1/{appCode}` |
| capability | 一般由套餐带出；手工调整时填 capability JSON 数组 |

## 6.4 首次开通向导

`/admin/onboarding` 用于**全新客户**的首批交付材料生成，按
"租户 → 订阅 → console deployment → license → runtime token → bundle" 一次性产出。

需要填：订阅计划、部署模式、企业端部署 URL、根应用 appCode、Console basePath、Platform Base URL、License 到期、Runtime Token 到期。

生成结果在页面右侧，包含交付给客户的配置。**Runtime Token 属于凭证**，交付时走安全渠道，不要贴在工单或聊天记录里。

单租户进度在 `/admin/onboarding/{tenantCode}` 跟踪。

## 6.5 订阅生命周期

| 事件 | 规则 |
| --- | --- |
| 下单 | 下单即开通，不需要额外的人工"激活"动作 |
| 对公转账订单 | 确认到账后，主订阅按**到账日期**激活并进入 30 天试用期 |
| 首次订阅期限 | 30 天试用 + 1 年 |
| 续订 | 在现有到期日基础上 +1 年 |
| 续订时机 | 随时可续，不必等到临期 |
| 重复确认 | 订单确认有防重复保护，误点不会重复延期 |
| 停服 | 由运营手动执行，不自动停服 |

停服前务必：确认商务口径 → 通知客户 → 在租户详情页记录原因。停服会影响客户全员，属于不可逆操作。

## 6.6 变更订阅

加应用：回到 `/admin/subscriptions` 对新应用走一遍五步。
减应用：先与客户确认数据保留策略，再停用对应订阅——**停用不等于删数据**，客户的业务数据仍在其租户库中。
换套餐：在租户详情页调整订阅计划，License 的 capability 会随之重签，需要重新下发到部署。

## 6.7 检查清单：新客户上线

- [ ] 租户已建档，租户编码确认无误
- [ ] 订阅计划已选定，订单/到账状态清楚
- [ ] 每个要开通的应用都走完编排五步
- [ ] License 已签发且状态 active
- [ ] 部署已配置，连通性检查 passed
- [ ] 心跳已上报，版本与登记 Release 一致
- [ ] release gate 通过，开通阶段为 active
- [ ] 客户管理员已能登录 `/dashboard` 与 Console
- [ ] 已把 [tenant 手册](../tenant/README.md) 交付给客户管理员
