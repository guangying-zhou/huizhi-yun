# 01 平台概览与角色分工

## 1.1 汇智云是什么

汇智云是面向 20~500 人软件企业（及软硬结合企业）的作业与管理 SaaS，把研发项目、协作文档、销售经营、财务、资产、人员这几件事放在同一套组织目录和权限体系下。

作为运营方，你卖出去的不是一个应用，而是**一个租户 + 一组应用 + 一份部署**。

## 1.2 平台分层

```
运营控制台 (Platform /admin)          ← 你在这里工作
        │  下发订阅、License、策略包
        ▼
企业工作台 (Platform /dashboard)      ← 客户的平台管理员
        │
        ▼
企业控制台 (Console)                  ← 客户的企业管理员：目录、集成、凭证
        │
        ▼
业务应用 (Codocs / Aims / Altoc / Finance / Assets / People / Insights / Workflow)
```

- **Platform** 是控制面：管租户、订阅、部署、License、策略包和应用治理。
- **Console** 是企业侧基础运行时：管企业配置、组织目录、认证、凭证保险箱、集成配置。
- **业务应用**只消费 Console 下发的身份与权限结果，不自建一套用户体系。

## 1.3 应用清单

| 应用 | 名称 | 用途 |
| --- | --- | --- |
| `console` | 企业控制台 | 企业配置、目录、认证、凭证、集成 |
| `codocs` | 汇智云·文档 | 协作文档与知识管理 |
| `aims` | 汇智云·项目 | 研发项目全生命周期（PIVR 四阶段） |
| `altoc` | 汇智云·营销 | LTC 经营：客户→商机→合同→回款 |
| `finance` | 汇智云·财务 | 发票、收款、核销、费用、项目核算 🟡 |
| `assets` | 汇智云·资产 | 实物/资源/知识产权资产、采购、环境交付 |
| `people` | 汇智云·人员 | 员工事实、任职、成本快照、绩效周期 🟡 |
| `insights` | 研发效能 | 代码仓库贡献与效能分析 |
| `workflow` | 审批流程 | 通用审批引擎，被各应用调用 |
| `align` | 汇智云·协同 | 深度组织协同，可选增强 🟡 |

🟡 = 开发中，上架前先确认当前可交付范围。

## 1.4 关键概念

| 概念 | 含义 | 在哪维护 |
| --- | --- | --- |
| **租户 Tenant** | 一家企业客户，用 `tenant_code` 标识 | `/admin/tenants` |
| **订阅 Subscription** | 租户买了哪个计划、有效期多久 | `/admin/subscriptions` |
| **订阅计划 Plan** | 套餐：包含哪些应用与能力 | `/admin/plans` |
| **License** | 订阅生效后下发给部署的授权凭据 | `/admin/licenses` |
| **部署 Deployment** | 租户的运行环境（域名、runtime 地址） | `/admin/deployments` |
| **Manifest** | 应用申报的资源、动作、推荐角色清单 | `/admin/applications/{code}/manifests` |
| **Release** | 应用的一个可发布版本，来自 Git tag | `/admin/applications/{code}/releases` |
| **策略包 Policy Bundle** | 平台签名下发给租户的授权规则集 | 随订阅/角色变更生成 |

**Manifest 是权限的唯一技术事实源**——应用有哪些资源、哪些动作、推荐哪些角色，全部由 Manifest 声明。运营侧不要在别处另建一份权限清单。

## 1.5 运营角色分工

平台侧账号在 `/admin/accounts` 维护，权限由平台角色（`/admin/platform-roles`）控制。典型分工：

| 角色 | 主要职责 | 常用页面 |
| --- | --- | --- |
| 平台超级管理员 | 全部权限，含角色与账号管理 | 全部 |
| 产品/应用治理 | 应用接入、Manifest 审核、Release 发布 | `/admin/applications`、`/admin/runtime-releases` |
| 商务运营 | 租户建档、订阅开通、订单发票 | `/admin/tenants`、`/admin/subscriptions`、`/admin/orders` |
| 交付实施 | 部署配置、连通性验收、开通闸门 | `/admin/deployments`、`/admin/onboarding` |
| 客户支持 | 工单、公告、问题排查 | `/admin/tickets`、`/admin/announcements`、`/admin/audit` |

> 授权原则：`admin` 只默认蕴含同一资源的 `view/edit/admin`；`approve`、`export`、`deploy` 这类敏感动作必须**显式**授权。给运营同事配权限时不要指望"给个 admin 就都能做"。

## 1.6 一句话记住边界

- 商业事实（买了什么、有效期）由**订阅**决定。
- 技术可用性（能不能连上、版本对不对）由**部署**决定。
- 两者都通过后，租户的开通阶段才会变成 `active`。**连通性通过 ≠ 开通完成**。
