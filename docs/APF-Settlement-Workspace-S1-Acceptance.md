# APF「收款与结算」S1 交付与验收

日期：2026-10-07。方案状态：已批准。范围依据：[简化方案 §3、§8](./APF-Sales-Finance-Simplification-Proposal.md)。

本批实现同一工作区，复用现有页面、组件和 BFF。没有 Runtime、数据库模型、grant、角色映射或职责分离规则变更。hzy0 切换由 Codex-sol 负责，本批未连接 hzy0 数据库、未写入生产业务、未切换或重启其进程。

## 1. 交付范围

| 路径/场景 | S1 行为 | 保留的边界 |
| --- | --- | --- |
| `/altoc/payments`、`/finance/receipts` | 同一“收款与结算”组件，分别默认待收款、到账记录 | 各入口沿用原领域导航权限；Finance 人员不依赖销售菜单权限 |
| 待收款、到账记录、待开票、待复核 | 复用服务端分页与状态筛选；首次访问视图才挂载，切回保留列表条件和页码 | “待复核”默认已确认到账，部分核销可切状态；是当前授权范围，不冒充新增的个人待办合同 |
| 选择单据 | 1440 为列表＋办理侧栏；390 为同页全宽上下文，返回列表保留位置与筛选 | 原独立详情 URL 仍有效，未退役旧 API |
| 登记到账/申请开票 | 从当前款项或财务单据携带客户、合同、结算计划、币种，保存后原位查看 | 不把 `customer_id` 当 `customer_code`；缺客户读取权限时提示读取失败，不猜关联；金额仍明确填写 |
| 到账分配 | 复用 B5-B 候选、版本、分配组和确认流程 | 到账确认人与核销人不同；不把建议或审批当成到账/核销结果 |
| 开票 | 复用申请、审批、正式开票组件；保存、审批、开票各自显示事实 | 申请人不能开自己的票；保存草稿不会自动批准或生成正式发票 |
| 历史与调整 | 当前合同可查看既有历史接续；已识别的调整路径可在侧栏查看 | 不执行 S2 自动接续；历史未就绪仍由原服务端规则拒绝；调整录入人不能确认/撤销自己的调整 |
| 跨人交接 | 复制定位到同一工作区/单据的链接，由对方登录后办理 | 不发送通知，不携带权限、身份或草稿金额；未保存的分配建议不跨人持久化 |

交接链接按对象领域选入口：财务单据固定从 `/finance/receipts` 打开，款项跟进从 `/altoc/payments` 打开。查询参数只定位对象，不能选择授权来源。普通会话仍使用合并授权，没有角色模拟入口或管理员豁免。

## 2. 授权与失败恢复

工作区用 Foundation 的静态 `AuthorizationModuleScope` 指明子组件所属模块。Finance 与 Altoc 分别读取原授权快照，不合并资源表；Finance 中的敏感动作仍经 Foundation 的现有动作蕴含逻辑判断。所属模块来自静态组件声明，未从 Cookie、Query 或单据内容推导。身份/策略变化沿用原快照清理机制，工作区同时清除关联上下文并重建办理区。

- 403：显示无权查看/办理，不保留可操作的旧详情，不显示“保存成功”。
- 503：读取故障与权限不足分开；读取失败没有保存结果文案。
- 409：B5-B 刷新最新资料，保留分配金额与选择；用户比较后重试。
- 写入结果未知：工作区表单保留原请求键与内容，暂时锁定输入，允许重试原请求；不换键重新登记。
- 切换单据或离开表单：有草稿时使用 Foundation 确认组件；取消离开后继续编辑。取消不发起业务写入。
- 三组异人规则保持服务端最终裁定；前端补充明确提示与禁用状态，不能代替服务端校验。

## 3. S0 合成任务基线与 S1 对照

按用户 2026-10-07 指令，用本地合成数据替代 hzy0 实页基线。基线源码为 `0cd02c80`，旧独立表单仍可在本分支访问；自动脚本验证旧 `/finance/receipts/new` 客户名称为空，而从款项进入的 S1 表单已携带关联字段。

计数口径：一次点击、一个业务对象选择、一个字段录入、一次确认各记一步；输入字数、打开选择器后翻页、登录和外部审批等待不计。下表是固定合成任务的步骤对照，不是生产计时。旧入口导航按基线可达路径计数；自动化覆盖旧表单空关联、S1 预填/保存/分配及失败恢复，未回放旧系统全流程。

| 固定任务与起点 | 原路径 | S1 | 结论 |
| --- | --- | --- | --- |
| 从款项详情进入到账表单并选好客户/合同/计划，尚未填金额 | 到账菜单→新建→选客户→选合同→选计划：5 步 | 登记到账：1 步，3 个关联自动带入 | 减少重复对象选择；不减少金额/日期/责任人等必要核验 |
| 从到账列表分配 60,000＋40,000 CNY | 详情→办理核销→填两笔金额→提交→确认：6 步，2 次业务页面切换 | 相同 6 步，列表与分配保留在工作区，0 次业务页面切换 | 没有宣称减少法定/内部复核动作 |
| 从款项详情新建开票申请草稿 | 开票申请菜单→新建→3 个关联选择→内容/金额→保存：8 步 | 申请开票→内容/金额→保存：4 步，原位显示申请详情 | 申请仍是草稿，后续审批和异人开票未计入这 4 步 |
| 历史合同尚未就绪 | 查看警示→进入历史接续→核验/按原规则办理 | 保留警示与同页历史入口；接续动作数量不变 | “正常历史合同零操作”属于 S2，本批不伪称完成 |
| 分配时发生 409 | 返回/刷新后比较，保留原输入再提交 | 同页刷新，两个金额保留；重试沿用同一请求内容时复用原键 | 异常处理可见，不吞冲突、不自动确认 |

合成对象：客户 `CU-SYNTHETIC`、合同 `CT-SYNTHETIC`、到账 `RC-SYNTHETIC-001`、两笔计划 `BS-SYNTHETIC-001/002`，金额 60,000/40,000 CNY；身份为 `cashier`、`reviewer`。这些对象不对应任何真实客户或凭据。

S1_PLAYWRIGHT_MODULE=<已安装的 playwright-chromium/index.mjs 路径> node enterprise/test/visual/settlement-workspace.mjs

## 5. 后续边界与回退

S2 才实施批次政策批准后的自动净期初接续；S3 才新增 D11 owning typed 调用收敛。本批不创建“统一结算”写 API、共享余额模型或新权限动作。四个任务视图复用现有查询，未增加“只属于我的复核”后端筛选合同，也不承诺财务 KPI 的跨域总计。

回退可恢复两处列表入口和导航标签；原 BFF、独立详情与业务事实保持兼容。S1 保存产生的是现有业务记录，回退 UI 不删除到账、申请、核销或接续证明。Aims 退役、部门协作与 hzy0 发布文件未纳入本次修改。
