# WizBiz vs Altoc Receivable Diff

- Date: 2026-06-24
- User symptom: legacy OA "有应收款" shows 128 contracts and receivable amount 17,640,055.68; new Altoc contract page with status "履约中" and "未回款额" card selected shows 153 contracts and 20,882,641.88.
- Diagnostic command added: `data-runtime/cmd/wizbiz-receivable-diff`. Run with `go run ./cmd/wizbiz-receivable-diff --env .env --samples 40`.
- Confirmed legacy screenshot count/amount is reproduced by `wizbizdb.wb_contract.contract_status = 0 AND exec_amount > 0`: 128 contracts, contract amount 39,900,952.42, receivable/unreceived 17,640,055.68.
- Confirmed new screenshot count/amount is reproduced by Altoc `contract.status = effective` and `amount_tax_inclusive - SUM(payment_record.received_amount) > 0`: 153 contracts, contract amount 40,808,271.03, unreceived 20,882,641.88.
- Difference decomposition: 1 old-positive contract excluded in new page because target status is terminated (`CTMIG845`, 14,501.26); 26 target-positive contracts are not old-positive because old `exec_amount` is zero/empty/negative but new computed unreceived is positive (total 2,377,637.46); 10 common contracts have amount differences from migrated/new payment records vs old `exec_amount` (net +879,450.00). These reconcile exactly to the 3,242,586.20 amount delta.
- Root cause: old OA "应收款" is a stored legacy ledger field (`exec_amount`), while new Altoc "未回款额" is a computed balance from contract amount and payment records. They are not the same business definition.
- Follow-up check for the extra target-positive rows: most legacy invoices/receipts have been migrated into Finance (`finance_invoice` / `finance_receipt`). The mismatch is that Altoc contract list computes `未回款额` from local `hzy_altoc.payment_record`, while the incremental migration writes receipts to Finance only. For rows such as `CTMIG2054`, `CTMIG4`, `CTMIG1665`, `CTMIG2014`, `CTMIG2003`, `CTMIG2038`, `CTMIG1636`, `CTMIG1616`, `CTMIG2032`, `CTMIG1828`, and `CTMIG2037`, source receipts and Finance receipts match but Altoc payment records are empty, so Altoc still shows the full contract amount as unreceived. A smaller subset has no source invoice/receipt rows either (for example `CTMIG1663`, `CTMIG3`, `CTMIG1185`, `CTMIG1`).
